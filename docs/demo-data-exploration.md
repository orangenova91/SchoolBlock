# 체험용 시간표 데이터 탐색 (테스트 시간표 4, 2026-10-15)

체험용 시간표(실제 학교 기반 SET 예시, `lib/demo-seed-set-example.json`)의 **교사·교과·시수는 그대로**
두고 SET 배치·선 수업·배정 불가·동일 교과 금지를 바꿔 v2로 생성했다. 그리고 정수계획법(HiGHS)으로
**수학적 최적**을 구해 비교했다. 결과는 사용자 계정의 "테스트 시간표 4"에 확정 버전 20개로 저장했다.

- 학교: 1·2·3학년 6·7·7반, 교사 39명, SET 11개(부분 SET 4개, 순환 과목 포함)
- 도구: `scripts/v2-perf/explore-demo.ts`(조건 생성·v2 실행), `scripts/v2-perf/samples.ts`(저장)
- 수치 표기: 점심 연강 / 3연강 / 동일 교과 같은 날 중복

## 1. 핵심 결론

1. **이 학교 데이터로는 0/0/0이 수학적으로 불가능하다.**
   - 점심 연강 최소값(정수계획법 증명): SET 원래 위치 고정 시 **11**, SET 위치까지 자유로 해도 **8**.
   - 선 수업·배정 불가를 하나도 넣지 않아도 그렇다. 교사 시수와 교과 배정 구조 때문이다.
     0/0/0을 원하면 교사 배정(시수 분배)을 바꾸거나 점심 연강 조건을 완화해야 한다.
2. **이론상 최선**
   - SET 고정(v2 방식): **11 / 18 / 1** (점수 72, 최적 증명)
   - SET 자유(v3 방향): **8 / 1 / 0** (점수 26, 하한 24 증명 → 최선은 8 / 0~1 / 0)
3. **v2의 수준**: 기준 조건에서 13 / 18 / 3(점수 84)로 최적(72)에 가깝지만,
   가장 엄격한 조건에서는 20 / 34 / 14(170) 대 최적 16 / 28 / 4(116)로 차이가 커진다.
4. **배치 가능 한계** (동일 교과 금지 전부, 원래 SET 위치): 배정 불가는 **약 5%까지**,
   선 수업은 **30%까지** 가능했다. 배정 불가 10% 이상은 대부분 배치 불가(정확 판정).
   현실 데이터는 SET이 교사 시간을 많이 쓰므로 배정 불가 여유가 작다.

## 2. 배치 가능 한계 탐색 (동일 교과 금지 전부, 원래 SET 위치, v2 20초)

행: 배정 불가(교사별 빈 시간의 비율), 열: 선 수업(공통 수업의 비율). "불가(n)"은 정확 판정상 최소 n교시 미배치.

| | 선 0% | 5% | 10% | 15% | 20% | 25% | 30% |
|---|---|---|---|---|---|---|---|
| 불가 0% | 12/19/3 | 15/21/5 | 13/19/4 | 16/24/5 | 15/28/5 | 15/29/9 | 16/34/4 |
| 5% | 12/21/7 | 12/24/3 | 불가(1) | 16/29/7 | 14/26/3 | 15/25/6 | 불가(1) |
| 10% | 불가(1) | 불가(2) | 불가(1) | 불가(2) | 불가(3) | 불가(2) | 18/38/12 |
| 15% | 불가(2) | 불가(3) | 불가(2) | 불가(4) | 19/35/15 | 불가(5) | 불가(7) |
| 20% | 불가(2) | 불가(4) | 불가(5) | 불가(4) | 불가(4) | 불가(6) | 불가(7) |
| 25% | 불가(10) | 불가(11) | 불가(11) | 불가(13) | 불가(5) | 불가(8) | 불가(13) |
| 30% | 불가(12) | 불가(19) | 불가(12) | 불가(13) | 불가(20) | 불가(10) | 불가(17) |

- 무작위로 만든 조건이라 칸마다 운이 섞인다 (예: 5%·10%는 불가, 5%·15%는 가능).
- 배치 가능한 경우 선 수업·배정 불가가 늘수록 3연강·동일 교과가 늘어난다.
- SET 위치까지 함께 최적화하는 v3 프로토타입으로 같은 표를 돌려도 배치 가능 범위는 거의 같았다
  (배정 불가가 원래 SET 시간을 피해 만들어져, SET을 옮기면 오히려 부딪힘).

## 3. 저장한 확정 버전 (테스트 시간표 4)

입력 데이터·작업본은 e01(원래 SET, 동일 교과 금지 전부, 선 수업·배정 불가 없음)이다.

| 확정 | 조건 | 결과 |
|---|---|---|
| 1 | e01 원래 SET · 동일 교과 전부 (기준) | 13 / 18 / 3 |
| 2 | e02 원래 SET · 동일 교과 원래 7개 | 12 / 17 / 0 |
| 3 | e03 원래 SET · 동일 교과 국수영 | 12 / 19 / 2 |
| 4 | e04 SET 자동 배치 | 26 / 7 / 1 |
| 5 | e05 SET 점심 앞뒤 회피 | 28 / 7 / 1 |
| 6 | e06 SET 점심 앞뒤 우선 | 17 / 5 / 3 |
| 7 | e07 SET 무작위 | 20 / 12 / 0 |
| 8 | e08 SET 요일 분산 | 22 / 6 / 1 |
| 9 | e09 SET 요일 몰림 | 21 / 36 / 14 |
| 10 | e10 SET 대각선 순환 | 13 / 17 / 1 |
| 11 | e11b 배정 불가 5% · 선 수업 20% | 13 / 26 / 6 |
| 12 | e12 배정 불가 10% · 선 수업 30% | 20 / 38 / 14 |
| 13 | e13 배정 불가 15% · 선 수업 20% (가장 엄격, 배치 가능) | 20 / 34 / 14 |
| 14 | e14 선 수업 30% | 15 / 30 / 5 |
| 15 | m15 [정확 최적] 원래 SET 고정 | **11 / 18 / 1** |
| 16 | m16 [정확 최적] 가장 엄격 조건, 원래 SET 고정 | **16 / 28 / 4** |
| 17 | m17 [v3 정확 최적화 실험] SET 위치까지 자유 | **8 / 1 / 0** |
| 18 | x17 [v3 프로토타입] 기준 | 12 / 11 / 0 |
| 19 | x18 [v3 프로토타입] 배정 불가 5% · 선 수업 20% | 11 / 18 / 5 |
| 20 | x19 [v3 프로토타입] 가장 엄격 | 17 / 37 / 11 |

- 배정 불가 5% · 선 수업 10%(e11)는 정확 판정상 배치 불가(최소 1교시)라 저장하지 않았다.
- 1~14는 v2(30초). 15~17은 정수계획법 해(15·16은 최적 증명, 17은 20분 제한, 하한 24 대 해 26).
  18~20은 SET 이동 교환 개선 프로토타입(30초).
- 버전마다 조건(선 수업·배정 불가·SET 위치)이 다르므로, 입력 화면은 e01 기준이다. 버전은 결과 시간표로만 비교한다.

## 4. SET 배치 방식별 (동일 교과 금지 전부, 다른 제약 없음)

- 원래(실제 학교) 배치가 점심 연강에 가장 좋다(13). 앱 자동 배치·점심 회피는 26~28로 두 배.
- 3연강은 반대로 자동·점심 회피·분산이 낮다(6~7). 원래·대각선 배치는 SET끼리 이어져 17~18.
- 요일 몰림은 모두 나쁘다(21 / 36 / 14).
- SET을 고정하면 어떤 배치든 점심 연강·3연강 중 하나가 높다. 둘 다 낮추려면 SET 위치를
  생성 단계에서 정해야 한다(m17: 8 / 1 / 0).

## 5. 시사점

- **입력 데이터의 한계 진단**: 이 학교는 선 수업·배정 불가 없이도 점심 연강 8건이 불가피하다.
  어떤 교사가 원인인지 알려 주는 진단(정수계획법으로 점심 연강 최소화 → 남는 교사 표시)이 v3 사전 검사 후보다.
- **정수계획법 활용**: SET 고정 조건의 최적해를 1~1.5분에 증명했다. 생성 시간 안에 근사 최적을
  얻는 방식(시간 제한 정수계획법, 부분 재최적화)이 v2·v3 품질 개선 후보다.
- **배정 불가 여유**: 실제 데이터는 배정 불가 5% 안팎에서 한계가 왔다. 입력 단계의 실시간 경고가 필요하다.
