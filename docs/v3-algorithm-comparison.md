# v3 3단계: 알고리즘 비교 (2026-10-16)

명세: [v3-model-spec.md](v3-model-spec.md). 기본값을 그대로 적용했다.
- 같은 SET 하루 1회: 자유 SET은 필수
  - 이 규칙의 비용을 따로 계산했다. K1·K2 모두 규칙이 있든 없든 이론상 최선이 24로 같았다(손해 0).
  - 다만 규칙을 빼면 최적해에 하루 2회 SET이 5건 생겼다.
- 근접 기준: 이론상 최선 대비 10% 이내 또는 6점 이내

## 1. 비교한 방식 (비유로 설명)

시간표 만들기를 **큰 퍼즐 맞추기**에 비유한다. 조각(수업)마다 놓을 수 있는 자리가 정해져 있고, 다 맞춘 뒤 "보기 좋은 정도"(점수)를 따진다.

| 방식 | 하는 일 | 비유 |
|---|---|---|
| **A. 탐색** (교환 개선, v2 방식 확장) | 일단 다 맞춘 퍼즐에서 두 조각을 바꿔 보고, 좋아지면 남긴다. 가끔은 조금 나빠지는 교환도 받아들여 막다른 길을 피한다. SET 회차 이동과 순환 교사 맞바꾸기도 포함한다 | 사람이 퍼즐을 계속 이리저리 바꿔 보며 다듬기. 빠르지만, 정답에 얼마나 가까운지는 모른다 |
| **B. 정수계획법 단독** | 모든 조건을 수식으로 바꿔 수학 계산기(HiGHS)에 통째로 맡긴다. 답과 함께 "이보다 좋을 수는 없다"는 하한도 준다 | 모든 경우를 체계적으로 따지는 계산기. 작은 문제는 정답을 증명하지만, 큰 문제는 시간 안에 답을 하나도 못 낼 수 있다 |
| **D. 혼합** (탐색 → 부분 재계산) | 탐색으로 빠르게 만든 시간표에서, 하루 또는 한 학년의 이틀 정도만 비우고 그 부분을 정수계획법으로 다시 최적으로 채운다. 이를 반복한다 | 완성된 퍼즐에서 한 구역만 들어내 전문가가 그 구역을 최적으로 다시 맞추고, 다른 구역으로 옮겨 가며 반복 |

(C. SET 먼저 고정 후 공통 수업 최적화는 [순서 실험](v3-set-order-test.md)에서 이미 탈락했다. 이론상 최선보다 2.5~4배 나쁘고, 순환 교사 겹침 때문에 배치 불가도 생겼다.)

## 2. 실험 조건

| 조건 | 내용 | 이론상 최선 |
|---|---|---|
| K1 | 체험용 데이터(실제 학교 기반 21반), 제약 없음 | 24 (증명) |
| K2 | K1 + 배정 불가 5% + 선 수업 5% | 24 (증명) |
| K3 | K2 + SET 절반 사용자 고정 | 52 (증명) |
| K4 | 가상 학교 48반(학년당 16반), 교사 부하 20시간, 부분 SET 포함, 배정 불가 5%, 선 수업 5% | 15~23 (정수계획법 1시간: 해 23, 하한 15, 증명 못 함) |
| K5 | 가상 학교 48반, SET 많음, 부하 19시간 — 어려운 조건 | **배치 불가: 최소 미배치 2교시 (증명, 9.7분)** |

- 시간: 60초(빠름) / 300초(표준). A·D는 3회 반복(무작위성), B는 1회(결정적).
- 모든 결과는 검증기(명세 H1~H11)를 통과했다.
  K3의 "같은 SET 하루 2회" 1건은 사용자가 고정한 원래 학교 배치(F SET 화요일 2회)라 정상이다.

## 3. 결과 (점수, 낮을수록 좋음. 3회 각각)

| 조건 | 시간 | A. 탐색 | D. 혼합 | B. 정수계획법 |
|---|---|---|---|---|
| K1 (최선 24) | 60초 | 32 · 27 · 27 | 29 · 34 · 33 | 해 없음 |
| | 300초 | **24 · 27 · 24** | 27 · 28 · 30 | 28 (하한 23) |
| K2 (최선 24) | 60초 | 47 · 53 · 34 | **38 · 39 · 48** | 해 없음 |
| | 300초 | 41 · 39 · 34 | **39 · 38 · 31** | 224 |
| K3 (최선 52) | 60초 | 78 · 83 · 81 | **62 · 64 · 68** | 해 없음 |
| | 300초 | 71 · 75 · 67 | 58 · 63 · 58 | **52 (최적 증명)** |
| K4 (48반, 최선 15~23) | 60초 | 106 · 76 · 106 | 97 · 88 · 97 | 해 없음 |

| K5 (배치 불가, 최소 2) | 60·300초 | 미배치 2~4 | 미배치 3 (보완판) | 해 없음 (1시간) |

## 4. 해석

1. **모든 경우에 이기는 방식은 없다.**
   - 쉬운 문제(K1): 탐색(A)이 300초에 최선(24)에 도달했다.
   - 제약·고정·큰 학교(K2~K4): 혼합(D)이 가장 좋았다. K4 300초에서 탐색 평균 82, 혼합 평균 54.
   - 작은 문제(K3: SET 절반 고정으로 변수가 줄어듦): 정수계획법(B)이 5분 안에 정답을 증명했다.
   - 정수계획법 단독은 60초에는 어떤 조건에서도 해를 못 냈고, 48반 학교는 300초에도 해를 못 냈다.
2. **같은 방식도 회차마다 차이가 크다** (K4 혼합 32~70). 여러 번 돌려 가장 좋은 것을 고르면 결과가 안정된다.
3. **5분으로는 "근접"에 못 미치는 경우가 많다.** K4는 정수계획법을 1시간 돌려야 23점이 나왔고, 5분 혼합의 최고는 32점이었다.
   - K1(24~27)과 K3(B 52, D 58)은 근접 기준(차이 6점 이내)을 만족했다.
   - K2는 최선 31 대 최선 24로 7점 차이다.
4. **K5는 SET 위치를 자유로 해도 미배치 2교시가 남는 조건이다** (정수계획법으로 증명).
   이런 경우 v3는 시간표를 만들지 않고 원인을 안내해야 한다.
   - 탐색의 최고 결과(미배치 2)는 이 최소값과 같았다.
   - 다만 이 판정에 약 10분이 걸렸다. SET 고정 판정(v2)은 수 초였으므로, SET 자유 조건의 배치 가능 판정을 빠르게 하는 방법이 4단계(진단 설계)의 과제다.

## 5. 결론과 권장 구성 (안)

**"여러 방식 동시 실행(포트폴리오)"** 방식을 권장한다. 같은 시간 동안 다음을 함께 돌리고, 가장 좋은 시간표를 고른다.

| 역할 | 방식 | 이유 |
|---|---|---|
| 빠른 첫 해 | 탐색(A) | 수 초 안에 미배치 없는 시간표를 만든다. 쉬운 문제는 이것만으로 최선에 도달 |
| 품질 개선 | 혼합(D) 2~3개 (서로 다른 무작위 시작) | 제약이 있거나 큰 학교에서 가장 좋았다 |
| 기준선(하한)과 작은 문제 | 정수계획법(B) | 하한을 계산해 "근접" 판정과 안내에 쓴다. 작은 문제는 정답 증명까지 |

- 탐색 시간 단계(안): 빠름 1분 / 표준 5분 / 정밀 20~30분. 진행 중 현재 최선과 하한을 보여 주고, 근접 기준에 들면 일찍 끝낼 수 있다.
- 실행 구조(5단계)에 주는 영향: 여러 방식을 동시에 몇 분씩 돌리므로, 웹 요청 안에서 끝내는 지금 구조로는 어렵다. 작업 큐·별도 작업 프로세스(1단계 대안 A~C)가 필요하다.
- 구현 언어: 실험은 Python(scipy의 HiGHS)으로 했다. 앱은 이미 같은 HiGHS를 JavaScript(WebAssembly)로 쓰고 있다(v2 정확 판정). 속도 차이는 5단계에서 측정한다.

## 6. 이 단계에서 찾아 고친 문제 (실험 도구)

- 탐색 프로토타입이 SET 회차 안의 교사 겹침을 놓쳤다.
  - 원인: 앱 추천 순환 교사에서 한 교사가 같은 시간에 두 과목을 맡는 경우.
  - 조치: 고친 뒤 1·2차 실험을 다시 측정했다. 결론은 같았다.
- 탐색이 "같은 SET 하루 2회"를 위반으로 세지 않던 경우를 위반으로 세도록 고쳤다.
- 정수계획법 모델의 "동일 교과 같은 날" 세는 법을 앱과 같게 바꿨다 (묶음당 1건).
- 혼합 방식이 미배치가 있는 시작 해도 받도록 보완했다 (미배치 1교시 = 1000점).

## 7. 한계

- 학교 데이터는 실제 기반 1곳과 가상 학교 2개뿐이다. 가상 학교의 교사 배정은 실제와 다를 수 있다.
- 탐색·혼합은 프로토타입이고, 조정(교환 비율, 이웃 크기)은 하지 않았다.
- 정수계획법은 HiGHS 한 가지만 썼다. 상용 계산기나 OR-Tools(CP-SAT)는 비교하지 않았다.
