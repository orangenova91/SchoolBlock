# 시간표 생성 로직 v3 기본 설계 방향 (초안)

v3는 v2(`docs/v2-timetable-logic.md`)에서 확인한 한계를 풀기 위해 **입력 단계까지 조정**하는
모델이다. 가장 큰 변화는 **SET 블록 위치를 사용자가 먼저 고정하지 않고, 생성 단계에서 공통 수업과
함께 정한다**는 것이다. 학교의 기본 구조(학반·요일, 교과, 교사)와 학교 요구사항(선 수업,
배정 불가)은 그대로 유지한다.

> 상태: 설계 초안. v2 담당자 검토 결과와 아래 "결정이 필요한 사항"에 따라 바뀔 수 있다.

---

## 1. v2에서 확인한 근거

| 확인한 사실 | 근거 | v3에 주는 의미 |
|---|---|---|
| 우선 배치(동일 교과·점심) 단계는 결과에 기여하지 않음 | 유지율이 우연 수준(15%), 18개 조합 품질 동일 | 단계 없이 생성 하나로 통합 (v2에서 이미 적용) |
| 사전 검사의 정확 판정(정수계획법)이 빠르고 정확 | 실제 규모 0.2~1.5초, 48개 반 5.8초. 빠른 검사가 놓친 경우도 잡음 | v3 사전 검사의 중심. SET 위치까지 포함해 확장 |
| SET 위치 고정이 품질의 하한을 정함 | 데모 데이터 A: SET 고정 시 점심 연강 하한 25, 3연강 7. SET 이동 허용 시 점심 8~12, 3연강 0~3 (같은 SET 같은 날 금지 포함) | **SET 위치를 생성 변수로** |
| SET 배치 방식에 따라 점심 연강과 3연강이 맞바뀜 | 성능 측정: 점심 회피 → 3연강 4, 요일 분산 → 점심 7, 몰림 → 3연강 5 | 사람이 미리 정하기보다 점수로 함께 최적화 |
| SET 자동 배치가 점심 앞뒤를 피함 | `set-blocks-auto.ts`의 slotScore(점심 교시 +15) | 공통 수업이 점심 앞뒤에 몰리는 원인 |
| 품질을 떨어뜨리는 입력 요인 | 교사 부하, SET 비중, 배정 불가·선 수업 비율 | 입력 단계에서 미리 경고 |
| 현실적인 조합도 배치 불가가 될 수 있음 | 큰 학교 + 요일 불가 20% + 무작위 10% + 선 수업 10% → 불가 1교시 | 입력 단계에서 빠른 경고, 최종 단계에서 정확 판정 |
| 같은 반 안에서 두 칸 교환 + 담금질이 효과적 | 3연강 47 → 7, 교환 수십만 회/초, 개선 정체 시 종료 | v3 탐색의 기본. SET 이동용 교환을 추가 |

## 2. 목표

1. **미배치 0 보장**: 배치 가능한 조건이면 반드시 완전 배치하고, 불가능하면 생성 전에 이유와 함께 알린다.
2. **선호 조건 최소화**: 점심 연강·3연강·동일 교과 같은 날 중복을 SET 위치까지 포함해 최소화한다.
3. **학교 요구 유지**: 1~3단계(학반·요일, 교과, 교사), 선 수업, 배정 불가는 그대로 둔다.
   SET 시간을 꼭 정해야 하는 학교는 일부 칸을 **선택적으로 고정**할 수 있게 한다.
4. **입력 중 조기 경고**: 선 수업·배정 불가를 입력하는 순간, 배치 불가나 품질 저하 위험을 숫자 근거로 보여준다.

## 3. 단계 구성 (안)

| 단계 | v1·v2 | v3 (안) |
|---|---|---|
| 1 | 학반·요일 설정 | 동일 |
| 2 | 교과 설정 (SET 구성 포함) | 동일 |
| 3 | 교사 배정 | 동일 + SET 순환 교사(여러 교사가 한 과목을 나눠 맡음) 시수 입력 |
| 4 | **SET 블록 배치 (필수)** | **SET 확인·선택 고정**: 배치는 하지 않음. 꼭 필요한 SET 칸만 "고정" 또는 "희망 시간대"로 표시 |
| 5 | 선 수업 배치 | 동일 + 실시간 경고 |
| 6 | 배정 불가 설정 | 동일 + 실시간 경고 |
| 7 | 추가 조건 설정 | 동일 + 선호 가중치(v2 패널 이동), SET 관련 선호(예: 1교시 SET 회피) |
| 8 | 시간표 생성 | 사전 검사(SET 포함 정확 판정) → **SET + 공통 수업 동시 생성** → 결과 확인·조정 |

- SET 단계의 위치는 담당자 검토로 정한다. 후보는 두 가지다.
  - (a) 지금 자리(3단계 뒤)에 두되 "확인·선택 고정"으로 바꾸는 안
  - (b) 배정 불가 뒤로 옮기는 안
- 선 수업·배정 불가 화면은 지금 SET 위치를 기준으로 충돌을 검사한다. v3에서는 SET이 아직
  정해지지 않으므로 검사 기준을 바꾼다.
  - 기존: 이 칸이 SET 칸인가
  - v3: **이 칸을 막아도 SET이 들어갈 자리가 충분한가** (아래 5절의 SET 수용 검사)
- 생성 결과 화면에서 마음에 드는 SET 배치를 "고정"하고, 공통 수업만 다시 생성하는 흐름을 둔다.

## 4. 생성 모델

### 4.1 결정 변수

- `x[g,s]`: 공통 수업 묶음 g(교사·반·교과)의 1시간을 칸 s에 둔다 (v2와 같음).
- `y[k,t]`: SET k의 한 회차를 학년 시간 t에 둔다. 전학년 SET은 그 학년 모든 반을,
  부분 SET은 해당 반들을 차지한다.
- `z[k,t,교사]`: 순환 과목에서 회차 t를 어떤 교사가 맡는지 (순환 과목만).

### 4.2 필수 조건

- 반 한 칸에 수업(공통 또는 SET) 1개
- 교사 한 시간에 수업 1개 (SET 교사 포함, 학년 간 포함)
- SET 회차 수 = 시수, 같은 SET은 하루 1회(기본, 학교 설정으로 완화 가능)
- 부분 SET끼리 반이 겹치면 같은 시간 불가
- 선 수업, 배정 불가, SET 고정 칸 준수
- 순환 과목: 교사별 맡은 회차 수 = 입력한 시수

### 4.3 선호 조건 (점수)

- v2와 같음: 점심 연강, 3연강, 동일 교과 같은 날 중복 (가중치 선택)
- 추가 후보: SET 1교시·마지막 교시 회피, SET 요일 분산, 학년 간 SET 시간 정렬 등.
  학교 요구를 확인한 뒤 정한다.

### 4.4 풀이 전략 (단계별)

1. **사전 검사**
   - 빠른 검사(수 ms)와 SET 수용 검사로 즉시 경고한다.
   - 정확 판정(정수계획법)에 SET 변수 `y`를 넣어 "SET 위치까지 포함해 미배치 0 배치가 존재하는가"를 증명한다.
   - v2 판정에 SET 회차 변수가 학년당 수십 개 더해지는 정도라, 현재 판정 시간(0.2~6초)에서 크게 늘지 않을 것으로 예상한다. 검증이 필요하다.
2. **초기 배치**: 정확 판정이 찾은 배치안(SET 위치 + 공통 수업)에서 출발한다.
3. **교환 개선 (v2 확장)**
   - 같은 반 두 칸 교환 (v2 그대로)
   - **학년 열 교환**: 한 학년의 두 시간을 통째로 바꿔 SET을 공통 수업과 함께 옮긴다. 실험에서 효과를 확인했다.
   - **부분 SET 교환**: 해당 반들만 두 시간을 맞바꾼다.
   - 같은 SET 같은 날 금지, 교사 겹침을 점수(필수 1000점)로 관리한다. 종료 규칙은 v2와 같다(개선 정체 시 종료, 상한 시간).
4. **(선택) 부분 정확 최적화**
   - 교환 개선이 멈춘 뒤, 특정 요일이나 교사 묶음만 풀어 정수계획법으로 다시 최적화하는 방식(LNS)을 검토한다.
   - 선호 점수를 더 낮출 여지가 있는지 v3 측정에서 판단한다.

## 5. 입력 단계 경고 (조기 경고)

v2 검토에서 정리한 기준을 단계 화면에 붙인다. 고정된 숫자 기준이 아니라 입력 상태에서 계산한다.

| 등급 | 기준 | 계산 | 화면 |
|---|---|---|---|
| 배치 불가 | 반·교사별 최대 매칭 부족 ≥ 1 | 빠른 검사 (수 ms) | 선 수업·배정 불가 입력 즉시 |
| 배치 불가 | SET 수용 부족: SET이 들어갈 수 있는 시간(그 학년 해당 반들과 SET 교사가 모두 비는 시간) < SET 시수, 또는 그런 시간이 걸친 요일 수 < SET 시수 | SET 회차 ↔ 시간 매칭 (수 ms) | 선 수업·배정 불가 입력 즉시 |
| 배치 불가 | 정확 판정 불가 | 정수계획법 (수 초) | 최종 단계 (v2와 같음) |
| 경고 | 교사 부하(남은 시수 ÷ 가용 시간) ≥ 85~90%, 반·교사 후보 배수 < 1.5 | 즉시 | 교사·배정 불가 화면 |
| 품질 주의 | 선 수업 비율 > 20%, 교사별 "위반 없이 넣을 수 있는 최대 시수" 초과, 동일 교과 가능 요일 < 시수 | 즉시 | 선 수업·추가 조건 화면 |

경고 수치(85~90%, 1.5, 20%)는 v2 측정에서 나온 잠정값이라 v3 측정으로 보정한다.

## 6. 데이터 변경 (안)

- `terms.logicVersion: "v3"` (v1·v2와 나란히 비교)
- SET 배치: 입력값(`setBlocks.cells`)이 아니라 **생성 결과**가 된다.
  입력에는 선택 고정만 남긴다 (예: `setBlocks.pins`, `setBlocks.preferredSlots`).
- 순환 교사 배정(`teacherAssignments`)도 입력이 아니라 생성 결과로 바뀐다.
- 사전 검사 결과 재사용(`v2PlacementChecks`)과 가중치(`v2Weights`)는 v3용으로 일반화한다.
  이름을 버전 공통으로 바꿀지는 담당자와 정한다.
- 기존 v1·v2 시간표를 v3로 옮기는 기능은 기본적으로 두지 않는다.
  필요하면 기존 SET 배치를 v3의 "고정"으로 가져오는 방식이 가능하다.

## 7. v2에서 재사용하는 것

| v2 구성 요소 | v3 활용 |
|---|---|
| 빠른 검사·정확 판정·결과 재사용 (`timetable-feasibility`, `timetable-exact-check`, `timetable-check-cache`) | SET 변수를 추가해 확장 |
| 교환 개선·종료 규칙·가중치 (`timetable-improved`, `v2-weights`) | 학년 열 교환·부분 SET 교환을 추가 |
| 사전 검사 진행 표시·결과 패널 (`v2-placement-panel`) | 그대로 사용, SET 결과 표시 추가 |
| 성능 측정 (`scripts/v2-perf`) | SET 배치 축을 "v3 자동"과 비교. 같은 시나리오로 v2 대 v3 측정 |

## 8. 검증 계획

1. 기존 측정 시나리오 36개를 v3로 돌려 v2와 비교한다. 특히 SET 비중 높음(점심 19), 교사 부하 높음(점심 11.7), SET 배치 방식 5종의 맞교환이 줄어드는지 본다.
2. 데모 데이터 A(점심 25, 3연강 7 하한)가 SET 이동 실험값(점심 8~12, 3연강 0~3)에 가까워지는지 확인한다.
3. 판정·생성 시간: SET 변수 추가 후 정확 판정 20초, 생성 30~60초 안에 드는지 확인한다.
4. 실제 학교 데이터 1~2곳 이상에서 검증한다 (v2에서도 남은 과제).
5. 순환 교사, 부분 SET, SET 고정 칸이 섞인 시나리오를 추가한다.

---

## 9. 결정이 필요한 사항 (담당자 검토)

1. SET 단계 위치: (a) 현 위치에서 "확인·선택 고정"으로 / (b) 배정 불가 뒤로
2. 학교가 SET 시간을 직접 정해야 하는 경우가 얼마나 흔한가 (고정 기능의 비중)
3. 같은 SET 하루 1회 규칙을 필수로 둘지, 학교 설정으로 둘지
4. SET 관련 선호 조건 (1교시·마지막 교시 회피, 학년 간 정렬 등)의 필요 여부
5. 창체·동아리처럼 학교 전체가 같은 시간에 하는 블록을 별도 고정 유형으로 둘지
6. v2의 선호 가중치 위치: 생성 단계 그대로 / 추가 조건 단계로 이동
7. 서버 점유 문제(생성 30~60초)와 배포 방식 — v3는 계산량이 더 커질 수 있다

## 10. 진행 단계 (안)

| 단계 | 내용 | 확인 방법 |
|---|---|---|
| M1 | SET 변수를 넣은 정확 판정 + SET 수용 검사 | 측정 시나리오 판정 시간, 소규모 전수 비교 |
| M2 | 교환 개선 확장 (학년 열 교환·부분 SET 교환) | 데모 A와 측정 시나리오에서 v2 대비 품질 |
| M3 | 단계 화면 변경 (SET 선택 고정, 입력 중 경고) | 브라우저 확인 |
| M4 | 순환 교사 자동 배정 | 순환 시나리오 |
| M5 | 종합 측정·문서화, v2와 비교 보고 | `scripts/v2-perf` 확장 |
