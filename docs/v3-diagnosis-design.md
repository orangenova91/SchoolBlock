시간표 생성의 계기판을 설계한다. 비유하면 다음과 같다.
- 출발 전 점검(입력 단계 경고)
- 운전 중 계기판(진행 표시)
- 도착 후 연비 안내(결과 평가)
- 고장 원인 알림(미배치 원인)

명세 [v3-model-spec.md](v3-model-spec.md), 정책 [v3-requirements.md](v3-requirements.md) 8절을 따른다.

## 2. 실험 결과

### 2.1 배치 가능 판정에 걸리는 시간

"풀린다"는 증명은 맞춘 퍼즐 하나를 보여주면 끝나서 빠르다. "안 풀린다"는 증명은 모든 경우를 따져야 해서 느리다.

| 조건 | 빠른 검사(세기) | 탐색으로 완성본 찾기 (60초, 2회) | 정확 판정(정수계획법) |
|---|---|---|---|
| F1~F4, F8 (가능) | 경고 없음 | **0.01~2.6초** 만에 미배치 0 | 2~139초 |
| F6 (가능) | 경고 없음 | 못 찾음 (미배치 1 남음) | 63초에 가능 증명. 혼합(정수계획 보수)으로 39초에 완성본 |
| F7 (불가 2) | 여유 없음 주의 1건 | 미배치 3~5 | 41초에 증명 |
| F9 (불가 4) | **0.02초에 "최소 4" 확정** | 미배치 8 | 194초에 증명 |
| F5 (불가 2) | **0.02초에 "최소 2" 확정** | 미배치 2~3 | 15분 안에 증명 못 함 (다른 실행에서 9.7분) |

- 정수계획법의 빠른 근사(LP 완화)는 모든 조건에서 0을 내서 판정에 쓸모가 없었다.
- **새로 찾은 세기 규칙**: 학년 전체 SET은 그 학년 모든 반을 차지한다. 그래서 교사가 그 학년에서 맡은 공통 수업은 SET 칸 밖에서만 할 수 있다.
  - 교사의 학년별 공통 수업 수가 (그 학년 시간 칸 − 학년 전체 SET 회차 합)보다 많으면, SET을 어디에 두든 그 차이만큼 미배치가 생긴다.
  - F5·F9의 미배치가 정확히 이 수만큼이었다. 정수계획법으로 수 분 걸린 판정을 0.02초에 같은 답과 원인까지 냈다.
  - 체험용(실제 학교 기반) 데이터에도 이 여유가 0인 교사가 있다. 이 교사와 관련된 배정 불가 1칸만으로 배치 불가가 될 수 있었다(F7).

### 2.2 미배치 원인 찾기

| 방법 | 결과 |
|---|---|
| 세기 규칙 (2.1) | F5·F9: 원인 교사와 부족 칸 수를 즉시 제시 |
| 최소 완화 계산: 배정 불가 칸·선 수업을 "풀 수 있는 조건"으로 바꾸고, 미배치 0이 되도록 가장 적게 푸는 방법 | **F7: 19초 만에 "교사 1명의 화요일 1교시 배정 불가 1칸만 풀면 가능"** (전체 배정 불가 149칸, 선 수업 16개 중). F9: 배정 불가·선 수업을 모두 풀어도 불가 → 원인이 교사 배정에 있음 (세기 규칙과 일치). F5: 15분 안에 결론 없음 |

### 2.3 데이터 한계 진단 (점심 연강 예)

- 체험용 데이터의 점심 연강 최소값은 8건이다(정확 계산 100초).
- 점심 연강이 생긴 6명 각각에 대해 그 교사만 최소화해 보면 모두 0건으로 만들 수 있었다.
  즉 **특정 교사 탓이 아니라 학교 전체의 수급 문제**다.
- 쉬운 설명용 세기: 월~목 점심 앞뒤 수업 칸은 160칸이다. 교사 39명이 하루 한 칸씩만 맡으면 최대 155칸이므로, **최소 5건은 연강이 될 수밖에 없다**(정확 최소는 8).

## 3. 설계

### 3.1 배치 가능 판정 흐름 (권장)

```
① 빠른 검사 (입력 화면, 수 밀리초, 항상)
   ├─ 확정 부족 발견 → "최소 N교시 미배치 확정 + 원인" 안내, 생성 버튼에 경고
   └─ 여유 없음 → 주의 표시
② 생성 시작: 탐색이 미배치 0인 완성본을 찾으면 = 배치 가능 증명 (대부분 수 초)
③ 30초 안에 못 찾으면: 정확 판정 + 혼합(보수)을 함께 실행
   ├─ 완성본을 찾음 → 배치 가능, 생성 계속
   ├─ 최소 미배치 > 0 증명 → 생성 중단, 원인 찾기(최소 완화 계산) 실행
   └─ 시간 안에 결론 없음 → 지금까지의 최선(미배치 수)과 하한을 보여주고 "판정 미완" 안내
```

### 3.2 원인 안내 종류

| 종류 | 계산 | 안내 예 |
|---|---|---|
| 세기 규칙 위반 | 즉시 | "체육 교사 ○○의 3학년 수업 10시간이 SET 밖 칸 8칸보다 많습니다 (2시간 부족)" |
| 최소 완화 | 수십 초~수 분 | "○○ 선생님 화요일 1교시 배정 불가를 풀면 배치할 수 있습니다" |
| 결론 없음 | — | "정확한 원인을 찾지 못했습니다. 남은 수업: ○○ (3학년 1반) 1시간 …" |

조건을 실제로 풀지는 사용자가 정한다. 시스템은 후보만 보여준다.

### 3.3 고정 손실·데이터 한계

| 항목 | 계산 비용 | 제공 방식(안) |
|---|---|---|
| 고정 손실 (고정한 SET 때문에 잃는 점수) | 정수계획법 2회, 1~12분 | 요청 시 계산 (버튼) |
| 데이터 한계 (항목별 최소값) | 항목당 1~2분 | 요청 시 계산. 세기 설명(예: 160칸 대 155칸)은 즉시 |

### 3.4 진행 표시와 결과 정보

| 구분 | 표시 항목 |
|---|---|
| 진행 중 | 경과 시간 / 최대 시간, 현재 단계(완성본 찾는 중·개선 중·판정 중), 현재 최선 점수, 이론상 최선(또는 범위), 근접 여부, 모은 결과 수(최대 3) |
| 결과마다 | 점수와 항목별 수치, 이론상 최선(범위), 근접 기준과 달성 여부, 사용한 방식, 걸린 시간 |
| 실패 시 | 최소 미배치 수(확정 또는 범위), 원인 안내, 남은 수업 목록 |

## 4. 결정 필요 사항

선택지별 장단점은 결정 요청 보고에서 설명했다. 기본값은 다음과 같다.
1. 판정 흐름: 3.1 (생성과 판정 통합)
2. 원인 찾기 대상: 배정 불가 칸, 선 수업 (+ 세기 규칙)
3. 고정 손실·데이터 한계: 요청 시 계산
4. "여유 없음" 표시: 주의(노란색)로 표시

## 5. 실험 도구 (작업 폴더)

- `quickcheck.ts`: 빠른 검사 규칙 5종
  - 반 시간
  - 교사 시간
  - SET 놓을 칸·요일
  - 학년 전체 SET 칸
  - 교사의 학년별 SET 밖 칸
- `diag.py`: 정확 판정, 최소 완화, 점심 연강 최소·교사별 분석
- `lns.py`: 혼합. 시작 해가 불완전하거나 필수 조건을 어겨도 보수해서 시작한다.
- `model.py`: 정수계획 모델. H12(같은 SET 요일 배분)와 완화 모드를 반영했다.
