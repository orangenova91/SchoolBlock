# v3 로컬 테스트 안내

로컬 개발 서버에서 v3 시간표 생성을 직접 시험하는 방법과, 그때 안에서 무슨 일이 일어나는지 정리한다.
로직 전체 설명은 [v3 로직](v3-timetable-logic.md), 배포는 [배포 방안](v3-deployment-plan.md)을 본다.

## 1. 준비

```bash
npm run dev
```

- 개발 서버가 뜨면 계산 작업자(조정자)가 **자동으로 함께 켜진다**. 터미널에 `[v3 작업자] …` 로그가 찍힌다.
- 동시에 계산하는 작업 수는 `V3_WORKER_CONCURRENCY` (기본 1). 여러 시간표를 동시에 시험하려면 `.env.local`에 `V3_WORKER_CONCURRENCY=4` 처럼 넣고 서버를 다시 켠다.
- 개발 서버를 끄면 계산도 멈춘다. 다시 켜면 1분(임대 시간) 안에 끊긴 작업을 다시 가져가, **마지막으로 끝난 구간의 중단점**에서 이어 간다 (진행 중이던 구간의 몇 분은 다시 계산).

## 2. 화면에서 시험하는 순서

1. 홈 → **새 시간표 작성(v3)**. 또는 기존 시간표를 내보내기 → 가져오기 할 때 v3로 만든다 (`scripts/v3-perf/make-terms.ts copy:<학기ID>`).
2. 1~7단계 입력은 v1과 같다. 4단계 **SET 고정 배치**에서는 시간이 정해진 SET만 칠하고, 나머지는 비워 둔다 (생성이 자동으로 놓음).
3. 8단계 **시간표 생성**
   1. **빠른 검사** 상자를 본다. 빨간 오류가 있으면 생성 버튼이 잠긴다. 적힌 항목을 고친다.
   2. 필요하면 **조건별 중요도**를 고른다 (점심 연강·3연강·같은 날 교과, 1~10점).
   3. **혼합(추천)** 을 누른다. "미리 승인"을 켜면 5분마다 묻지 않고 30분까지 이어 계산한다.
   4. 진행 패널이 2.5초마다 바뀐다: 지금까지 최고 점수, 이론상 최선, 목표, 모은 결과 수.
   5. 언제든 **멈추기**. 그때까지 찾은 가장 좋은 결과 3개가 나온다.
   6. 5분이 끝나면 **승인 대기**. 결과를 보고 **5분 더 계산**을 누르면 멈춘 자리에서 이어 간다.
   7. 결과 카드 3개를 비교하고 **시간표 보기**로 확인한 뒤 **이 결과 적용**. 현재 시간표가 되고 **확정 버전**에 쌓인다.
4. 페이지를 닫았다가 다시 열어도 작업 목록·진행·결과가 그대로 보인다.
5. 결과가 안 나오면(미배치) 빨간 안내 상자의 **배치 가능 판정 → 풀어야 할 조건 찾기**를 실행한다.

## 3. 안에서 일어나는 일

```
[브라우저]  생성 버튼
   │  POST /api/terms/{학기}/v3/jobs  (빠른 검사 통과 시에만)
   ▼
[MongoDB v3Jobs]  작업 #N "대기 중"  (+ 같은 입력의 하한이 없으면 "이론상 최선 2분" 작업도)
   ▲                                   │
   │ 2초마다 진행 저장·임대 연장          │ 대기 작업 가져가기 (학기당 1개만 실행)
   │                                   ▼
[조정자] 개발 서버 안, 웹 요청과 별개로 돈다 (DB 읽기·쓰기만)
   │  계산 스레드(worker_threads)를 하나 띄움 → 5분 구간 계산
   │  중지 요청은 공유 메모리로 1초 안에 전달
   ▼
[계산 스레드]  혼합: 탐색으로 시작 해 → 하루·학년 단위로 비우고 정밀 계산으로 다시 채우기 반복
   │  구간이 끝나면: 결과 3개(v3JobResults) + 중단점(v3Checkpoints, 30일) 저장 → 스레드 종료(메모리 반환)
   ▼
[다음 상태]  목표 달성+결과 3개 → 완료 / 미리 승인 → 다시 대기열 / 아니면 → 승인 대기
[브라우저]  2.5초마다 GET …/v3/jobs 로 상태 읽기, 결과는 구간이 끝날 때만 다시 받음
```

비유: 주문표(대기열)를 벽에 붙여 두고, 주방장(조정자)이 주문을 하나씩 요리사(계산 스레드)에게 넘긴다. 요리사는 5분마다 진행 상황을 적어 두므로, 중간에 바뀌어도 이어서 만들 수 있다. 홀(웹 화면)은 주방이 바빠도 계속 손님을 받는다.

### 점수와 목표

- 점수 = 점심 연강·3연강·같은 날 교과 건수 × 중요도의 합. **낮을수록 좋다.** 미배치가 있으면 시간표를 만들지 않는다.
- **이론상 최선**: 어떤 방법으로도 이보다 좋을 수 없는 점수. 2분 계산으로 정해진다. 작업자에 빈자리가 있으면(`V3_WORKER_CONCURRENCY` 2 이상) 생성과 동시에, 없으면 생성 구간이 끝난 뒤 돈다.
- 그 전에는 **0점을 하한으로** 쓴다 (점수는 0보다 작을 수 없음). 0점을 찾으면 곧 최선이고, 6점 이하는 "목표 달성"으로 표시된다.
- **목표**: 최선의 1.1배 또는 +6점 중 넉넉한 쪽 이하면 달성.
- **일찍 끝나는 때**: 엄격 기준(최선 × 1.05 또는 +3점 중 넉넉한 쪽) 안의 서로 다른 시간표 **3개**를 찾으면 멈추고 안내한다. 1~2개로는 멈추지 않고 5분까지 계산한다.
- 그 뒤 **추가 탐색 (최적해 3개)** 를 누르면 이론상 최선과 같은 점수의 시간표 3개를 찾을 때까지 5분씩 계산한다.
- 진단은 일찍 끝내지 않는다 (정해진 시간 안에서 끝까지).

### 대기열 규칙

| 규칙 | 값 |
|---|---|
| 같은 시간표 | 실행 1개 + 대기 3개 |
| 여러 시간표 | 5분 구간마다 돌아가며 (먼저 기다린 순) |
| 동시 계산 | 로컬 `V3_WORKER_CONCURRENCY` (기본 1), 버셀 Pro 서비스 기본 10 |
| 중단점 | 30일 보관. 입력을 바꾸면 이어 계산·적용 불가 → 새로 생성 |

## 4. 시험 도구 (선택)

| 명령 | 하는 일 |
|---|---|
| `npm test` | v3 단위 테스트 (103개) |
| `V3_TEST_USER=… V3_TEST_PASS=… npx tsx --tsconfig ./tsconfig.json scripts/v3-perf/make-terms.ts case:K4 copy:<학기ID>` | 시험 사례·기존 시간표로 "[v3 시험]" 시간표 만들기 (`--delete`로 모두 지움) |
| `… scripts/v3-perf/e2e-check.ts 이름=<학기ID> …` | 시간표마다 혼합 5분 → 하한 → 결과 → 적용을 자동으로 (실패면 진단) |
| `… scripts/v3-perf/api-check.ts` | API 흐름 19개 확인 (시험 시간표는 끝에 지움) |

## 5. 자주 보는 상황

| 상황 | 뜻 / 할 일 |
|---|---|
| 생성 버튼이 잠김 | 빠른 검사 오류. 상자에 적힌 교사·반·SET을 고친다 |
| "대기 중 (N번째)" | 앞 작업의 구간이 끝나면 시작. 같은 시간표는 한 번에 하나만 |
| "이론상 최선: 계산 중 · 0점 이상" | 하한 계산(2분)이 끝나면 표시됨. 동시 계산이 2 이상이면 생성과 함께 돎 |
| "최선임을 증명해 … 끝냈습니다" | 정수계획이 최선을 증명함. 더 계산할 것이 없음 |
| "입력이 바뀜" | 작업 뒤에 입력을 고쳤음. 이어 계산·적용 불가 → 새로 생성 |
| 결과 없음, 미배치 N시간 | 배치 가능 판정 → 풀어야 할 조건 찾기 (각 1분 안팎) |
| 개발 서버를 껐다 켬 | 1분 안에 마지막 중단점에서 이어 받음 (진행 중이던 구간은 다시 계산) |
