# v3 2단계: 문제 정식화 (수학 모델 명세)

이 문서는 v3 시간표 생성에서 "무엇이 올바른 시간표이고, 무엇이 더 좋은 시간표인가"를 정의한다.
구현 방식(교환 탐색, 정수계획법 등)과 무관하다. 모든 생성기, 사전 검사, 검증기는 이 정의를 따른다.

- 1단계 정책: [v3-requirements.md](v3-requirements.md)
- 근거 실험: [v3-set-order-test.md](v3-set-order-test.md), [v3-set-policy-test.md](v3-set-policy-test.md), [demo-data-exploration.md](demo-data-exploration.md)
- 실험용 구현: 작업 폴더의 `soft_opt.py`(정수계획법)가 이 명세의 초안 구현이다. 3단계에서 앱 코드로 옮긴다.

## 1. 기호와 입력

| 기호 | 뜻 | 앱 데이터 |
|---|---|---|
| g, c | 학년, 반 (c = 1..n_g) | `daySchedule.classCounts` |
| d, p | 요일(월~금), 교시 | |
| P_g,d | 학년 g의 d요일 교시 수 | `daySchedule.grades` |
| T_g | 학년 g의 시간 칸 집합 {(d,p) : p ≤ P_g,d} | |
| L | 점심 앞 교시 (점심은 L과 L+1 사이) | `generationPreferences.lunchAfterPeriod` |
| 공통 수업 묶음 l | (학년, 반, 과목, 교사, 시수 h_l) | 교사 배정 `classHours` (`expandCommonLessons`) |
| SET k | 학년 g_k, 회차 수 u_k, 차지하는 반 R_k, 과목별 담당 교사 | 교과 `set`·`classNo`·`units` (`catalogGradeSets`) |
| R_k | 전체 SET: 그 학년 모든 반 / 부분 SET: `classNo` 1..n인 반 (+α는 반을 차지하지 않음) | `homeRoomsForPartialSet` |
| 순환 과목 j ∈ k | 한 과목을 여러 교사가 나눠 맡고 교사별 시수 합 = u_k | `subjectsNeedingRotation` |
| F | 배정 불가 (교사, d, p) | `teacherConstraints.forbiddenSlots` |
| B | 선 수업 (반, 과목, 교사, d, p) | `subjectBlocks` |
| K_fix | 사용자가 배치한 SET 회차 (k, d, p) = 고정 | `setBlocks.cells` / `partialCells` (정책 실험 결과: 배치 = 고정) |
| A_fix | 사용자가 지정한 순환 교사 (k, j, d, p, 교사) | `setBlocks.teacherAssignments` |
| Ban | 같은 날 중복 금지 (학년, 과목) | `sameDaySubjectBans` |
| w_L, w_T, w_S | 선호 가중치 (기본 3/2/3) | v2 가중치 |

입력 검사(생성 전에 거르는 오류): SET 과목들의 `units` 불일치, 반 수 합 오류, 교사 시수 합과 교과 시수 불일치, 반별 수업 수 > 그 반의 시간 칸 수.

## 2. 결정 변수

| 변수 | 뜻 |
|---|---|
| x[l, d, p] ∈ {0,1} | 공통 수업 묶음 l을 (d,p)에 1시간 둔다 |
| y[k, d, p] ∈ {0,1} | SET k의 회차를 (d,p)에 둔다 (고정 회차는 1로 고정) |
| z[k, j, t, d, p] ∈ {0,1} | 순환 과목 j의 (d,p) 회차를 교사 t가 맡는다 (지정된 것은 고정) |

파생 값:
- 반 (g,c)가 (d,p)에 수업이 있다: Σ_l x + Σ_{k: c∈R_k} y
- 교사 t가 (d,p)에 바쁘다 busy[t,d,p]
  - 공통 수업: Σ x[l,d,p] (l의 교사가 t)
  - SET 회차: 비순환 과목 담당이면 y[k,d,p], 순환 과목이면 z[k,j,t,d,p]
  - 선 수업 상수

## 3. 필수 조건 (하나라도 어기면 "미배치"로 간주)

| 번호 | 조건 | 식 |
|---|---|---|
| H1 | 공통 수업 시수 | Σ_{d,p} x[l,d,p] = h_l (선 수업으로 채운 시간은 제외) |
| H2 | 반 한 칸 한 수업 | 반 (g,c)의 (d,p) 수업 수 ≤ 1 |
| H3 | 교사 한 칸 한 수업 | busy[t,d,p] ≤ 1 (모든 학년 합산) |
| H4 | 배정 불가 | (t,d,p) ∈ F 이면 busy[t,d,p] = 0 |
| H5 | 선 수업 유지 | B의 칸은 그대로 (반·교사 점유 상수) |
| H6 | SET 회차 수 | Σ_{d,p} y[k,d,p] = u_k |
| H7 | 고정 SET | (k,d,p) ∈ K_fix 이면 y = 1 |
| H8 | 전체·부분 SET 동시 금지 | 같은 학년의 전체 SET과 부분 SET은 같은 칸에 올 수 없다 (+α만 있는 부분 SET 포함) |
| H9 | 부분 SET 반 겹침 | H2에 포함 (R_k가 겹치는 부분 SET은 같은 칸 불가) |
| H10 | 순환 교사 | 회차마다 순환 과목 j의 담당 교사는 정확히 1명: Σ_t z = y. 교사별 맡는 회차 수 = 그 교사의 시수. 지정(A_fix)은 그대로 |
| H11 | 교사 SET 겹침 | H3에 포함 (다른 학년 SET, 같은 학년 다른 SET) |
| H12 | 같은 SET 요일 배분 | 층 높이 L(Σ_d max(F_d, L) ≥ u 인 최소 정수)에 대해 max(F_d, L−1) ≤ c_d ≤ max(F_d, L). F_d는 사용자가 고정한 회차 수. 자세한 예는 [요구사항 8.1](v3-requirements.md) |

미배치 수의 정의: 위 조건을 지키며 둘 수 없는 공통 수업 시간의 최소 개수다. 0이 아니면 시간표는 생성되지 않은 것으로 본다.

## 4. 선호 조건 (점수)

앱의 기존 진단 함수와 **같은 값**이 나오도록 정의한다. 교사는 SET 칸의 담당 교사도 포함한다.

| 번호 | 항목 | 정의 | 앱 함수 |
|---|---|---|---|
| S1 | 점심 연강 | 교사 t가 d요일 L교시와 L+1교시에 모두 수업 → 1건 | `listLunchTeacherDoubles` |
| S2 | 3연강 | 교사 t가 d요일 p, p+1, p+2에 모두 수업이고 점심을 걸치지 않음 → 1건. 겹치는 구간은 각각 셈 (4연속 = 2건) | `listTeacherTripleRuns` |
| S3 | 동일 교과 같은 날 | Ban 과목이 한 반 한 요일에 2시간 이상 → 1건 (3시간이어도 1건) | `listSameDaySubjectViolations` |

목적 함수: **최소화 w_L·S1 + w_T·S2 + w_S·S3** (필수 조건 H1~H11을 모두 지키는 해 중에서)

- 계층: 필수 조건은 점수와 바꿀 수 없다. 미배치 1건은 어떤 선호 점수보다 나쁘다.
- 선택 항목: 사용자가 끈 선호 항목은 가중치 0.

## 6. 출력과 진단

| 출력 | 정의 | 계산 방법(현재 근거) |
|---|---|---|
| 배치 가능 여부 | 미배치 최소값 = 0 인가 | 정수계획법 정확 판정 (v2의 `checkExactPlacement`를 SET 자유로 확장) |
| 미배치 원인 | 최소 미배치일 때 남는 반·교사·조건 | v2 `explainUnplaced` 확장 |
| 이론상 최선 | 목적 함수 최소값, 또는 증명된 하한 LB | 정수계획법 쌍대 한계 (실험: 3.5~12.5분에 증명) |
| 결과 품질 | 결과 점수 Z, 차이 = Z − LB | |
| 근접 판정 | **확정**: Z ≤ max(LB × 1.1, LB + 6). 조기 종료용 엄격 기준은 max(LB × 1.05, LB + 3) | 하한이 확정되지 않으면 범위로 표시 |
| 결과 목록 | 점수 순 상위 3개. 서로 30칸 이상이면서 5% 이상 달라야 함. 조기 종료는 상위 3개가 30초·20회 동안 바뀌지 않을 때 | [요구사항 8.5](v3-requirements.md) |
| 고정 손실 | (고정 조건 최선) − (고정 없는 최선) | 정수계획법 2회. 실험: 실제 학교 배치 전부 고정 시 72 대 24 |
| 데이터 한계 진단 | 항목별 최소값 (예: 점심 연강만 최소화했을 때 8건)과 원인 교사 | 항목별 정수계획법 (실험: 체험용 데이터 점심 연강 최소 8) |

사용자 안내 예: "이 조건에서 가능한 최선은 점수 24 (점심 연강 8건)입니다. 생성 결과 26점입니다(차이 2)."

## 7. 현재 앱과 다른 점·정해야 할 점

| 항목 | 현재 앱 | 명세 | 결정 |
|---|---|---|---|
| +α 과목 교사의 선호 집계 | 반 칸이 없어 SET 칸에 이름이 없음 → 점심 연강·3연강 집계에서 빠짐 (바쁨 처리는 됨) | 바쁜 교사 기준으로 모두 집계 | 명세 쪽으로 맞추는 안. 앱 진단을 바꿀지는 v1 영향 검토 후 |
| 동일 교과 같은 날 세는 법 | (반, 과목, 요일) 묶음당 1건 | 같음 | 실험 모델은 초과 시간 수로 셌음 → 앱 정의로 맞춘다 |
| 같은 SET 하루 2회 | 수동 배치 허용, 자동 배치 감점 | O1 옵션 | 통화 |
| SET 자동 배치와 배정 불가 | 자동 배치가 배정 불가를 보지 않음 (테스트 시간표 4에서 18건) | H4는 SET에도 적용 | v3 SET 배치는 배정 불가 반영 |
| 고정 SET 표시 | 직접 배치와 "자동 배치" 버튼 결과를 구분하지 않음 | 배치 = 고정 (K_fix) | v3 화면에서 자동 배치 버튼의 결과를 어떻게 다룰지 화면 설계에서 정함 |
| 순환 교사 미지정 | 나눠 맡는 교사 모두 바쁨 (보수적) | 생성기가 결정 (H10) | 확정 |
| 같은 SET 회차 안 교사 겹침 | 순환 교사 추천(`recommendSubjectRotations`)을 과목별로 따로 정해서, 한 교사가 같은 회차의 두 과목에 들어갈 수 있다 (체험용 데이터 2학년 C SET에서 3건). 바쁨 처리도 교사 이름을 합쳐 중복을 지우므로 겹침이 드러나지 않는다 | H3에 포함: 같은 회차의 서로 다른 과목에 같은 교사 불가 | 생성기는 과목별 담당을 따로 세어 검사. 앱 추천 기능 수정은 v1 영향 검토 후 |

## 8. 규모 (체험용 데이터 기준)

- 공통 수업 묶음 231개, SET 11개(35회차), 교사 39명
- SET 자유 정수계획법: 변수 약 8,900개, 조건 약 4,300개
- 48개 반 규모는 3단계에서 측정한다.

## 9. 검증

- **검증기**: 명세의 H1~H11, S1~S3를 그대로 계산하는 독립 검사기다. 실험용 `validate.ts`가 초안이며, H1·H2·H3·H4·H5·H6과 같은 SET 같은 날을 검사한다.
  - 정식 버전은 `lib/`에 테스트와 함께 둔다.
- 모든 생성 결과는 저장 전에 검증기를 통과해야 한다. 미배치가 있거나 필수 조건을 어기면 생성 실패로 처리한다.
- 점수는 앱 진단 함수와 같은 값이어야 한다. 테스트 시간표 3·4와 실험 결과로 대조한다.
- 이번 단계에서 검증기 덕분에 실험 모델 오류 2건을 찾았다.
  - SET 회차 누락
  - 고정 칸 위의 자유 SET
  - 이후 모든 실험 결과는 검증기를 거친다.
