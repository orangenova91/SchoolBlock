# v3 1단계: 목표와 성공 기준 (정책)

v3 설계 절차의 1단계 문서다. 담당자 통화(0단계) 전이라, 통화 결과에 따라 바뀔 수 있는
부분은 "설정 가능한 옵션"으로 열어 둔다.

## 1. 목적

- 여러 학교의 서로 다른 운영 방식에서 쓸 수 있는 시간표 생성 기능을 만든다.
- 학교의 기본 구조(학반·요일, 교과, 교사)와 요구사항(선 수업, 배정 불가, 동일 교과 금지 등)은
  입력 그대로 지킨다.
- SET 위치를 생성 단계에서 함께 정할 수 있게 해, SET 고정으로 생기는 품질 한계를 넘는다.
  단, **일부 SET을 고정하는 기능은 필수**다 (학교 사정으로 시간이 정해진 SET이 있을 수 있음).

## 2. 성공 기준

### 2.1 필수: 미배치 0

- 모든 수업이 배치되어야 한다. 미배치가 하나라도 있으면 **시간표가 생성되지 않은 것**으로 본다.
- 미배치 없이 배치할 수 없는 조건이면 생성 전에 알리고, 생성하지 않는다.
  안내에는 최소 몇 교시가 남는지, 어느 반·교사·조건이 원인인지를 포함한다.
- 제약 조건을 풀지(선 수업·배정 불가·SET 고정 조정)는 **사용자가 결정**한다. 시스템은 원인과 수치를 알려 줄 뿐 자동으로 풀지 않는다.

### 2.2 선호 조건: 수학적 최선에 근접

- 선호 조건(점심 연강, 3연강, 동일 교과 같은 날 중복 등)은 가능한 한 줄인다.
- 시스템은 현재 제약에서 **달성 가능한 최저 수준(이론상 최선)을 수학적으로 계산**해 사용자에게 안내한다.
  예: "이 조건에서는 점심 연강을 8건 아래로 줄일 수 없습니다."
- 생성된 시간표가 이론상 최선에 **근접하면 목표 달성**으로 본다.
  근접 기준은 3단계 실험에서 정한다(후보: 점수 차이 10% 이내 또는 지표별 2건 이내).
- 이론상 최선을 정확히 증명하지 못한 경우에는 증명된 하한과 찾은 해를 함께 보여준다 (예: "하한 24, 현재 26").

### 2.3 생성 시간

- 고정된 시간 제한은 두지 않는다. 대신 **사용자가 탐색 시간을 고를 수 있게** 한다.
  - 예: 빠름(약 30초) / 표준(수 분) / 정밀(수십 분)
- 오래 걸리는 생성은 진행률·현재까지의 최선·이론상 최선과의 차이를 보여 주고, 중간에 멈추고 그때까지의 결과를 쓸 수 있게 한다.
- 근거: SET 고정 조건의 최적 증명은 1~1.5분, SET 위치까지 자유로 둔 조건은 20분에도 최적 증명을 끝내지 못했다(해는 하한 대비 2점 차이).

## 3. SET 정책 (옵션으로 설계)

| 옵션 | 내용 | 비고 |
|---|---|---|
| SET 고정 범위 | 전부 자동 / 일부 고정 + 나머지 자동 / 전부 고정 | 일부 고정은 필수 기능 |
| 고정 단위 | SET 전체 / 특정 회차 / 희망 시간대(선호) | 통화로 확정 |
| 같은 SET 하루 1회 | 필수 / 선호 / 허용 | 현재 앱은 수동 배치 시 허용, 자동 배치는 선호 |
| 배치 패턴 | 대각선 순환 등 학교 규칙 | 실제 학교 예시에서 관찰. 통화로 확인 |
| 순환 교사 | 생성 단계에서 자동 결정 / 사용자 지정 유지 | 통화로 확정 |

## 4. 실행 구조 대안 (세부 검토는 배포 담당자와 협의 후)

| 대안 | 내용 |
|---|---|
| A. 현 구조 개선 | Next.js 서버 안에서 작업 큐 + 별도 작업 스레드/프로세스로 실행해 동시 요청이 막히지 않게 함 |
| B. 배포 방식 변경 | 서버리스 → 상시 실행 서버(컨테이너 등)로 바꿔 긴 작업 허용 |
| C. 계산 백엔드 분리 | 생성·판정을 별도 서비스로 분리 (예: Python + HiGHS/OR-Tools, 작업 큐). 웹은 요청·조회만 |
| D. 브라우저에서 실행 | 풀이기 WebAssembly를 사용자 브라우저에서 실행 (서버 부담 없음, 기기 성능 의존) |

## 5. 범위 밖

- 제약 조건의 자동 완화(어떤 선 수업·배정 불가를 풀지 결정)
- 학생 개인 수강 배정(어느 학생이 어떤 SET 과목을 듣는지)

## 6. 미결정 (담당자 통화)

- SET 고정 범위·단위, 같은 SET 하루 1회, 배치 패턴, 순환 교사 결정 방식
- 근접 기준 수치, 탐색 시간 단계
- 실행 구조 대안 선택

## 7. 참고: 현재 앱의 SET 동작 (코드 확인 결과)

### 7.1 배치하면 무엇이 고정되는가

- **전체 SET** (과목들의 반 수 합 = 학년 반 수, `catalogGradeSets`)
  - 월 3교시에 놓으면 그 학년 **모든 반의 월 3교시**가 그 SET 칸이 된다 (`buildSetCells`).
    반마다 과목은 과목의 `classNo`로 정해진다 (예: 1반 칸=물리, 2반 칸=화학).
  - 그 SET에 속한 **모든 과목의 교사**가 그 시간에 바쁜 것으로 처리된다
    (`teachersBusyForGradeSetAtSlot`).
  - 같은 학년의 부분 SET과 같은 시간에 둘 수 없다 (학년 전체 학생이 필요하므로).
- **부분 SET** (일부 반만)
  - 자기 반들(`classNo` 1..n)만 고정된다. +α(가상 반, n+1)는 반 칸을 막지 않는다.
  - 반이 겹치지 않으면 다른 부분 SET과 같은 시간에 둘 수 있다 (`partialRoomConflictAt`).
- **순환 교사** (한 과목을 여러 교사가 나눠 맡는 경우)
  - 회차마다 맡을 교사를 `teacherAssignments`(학년·SET·요일·교시·과목)로 지정한다.
  - 지정된 회차는 그 교사만 바쁘다. 지정이 없으면 나눠 맡는 교사 **모두** 바쁘다 (보수적).
  - 지정은 시간 칸에 묶여 있어, SET을 다른 시간으로 옮기면 기존 지정은 사라진다
    (`filterAssignmentsToPlacement`).
- **수동 배치 검사**: 시수 초과, 다른 학년 SET과의 교사 충돌, 부분 SET 반 겹침을 막는다.
  같은 SET이 하루 두 번 오는 것은 막지 않는다 (실제 학교 예시에도 있음). 자동 배치는 감점으로 피한다.
- **생성 단계**: SET 칸은 고정 입력이다. 생성은 SET 칸을 비운 나머지 칸에 공통 수업을 넣는다.

### 7.2 SET을 통째로 옮기기 (v3에서 쓸 이동 단위)

SET 한 회차를 옮긴다 = 그 회차의 **모든 반 칸 + 교사 묶음**을 함께 다른 시간으로 옮기는 것.
현재 데이터 구조로 그대로 표현되므로 생성·기존 로직에 문제가 없다. 지켜야 할 조건:

1. 옮길 시간의 그 반들 칸이 비었거나, 그 칸의 공통 수업을 맞바꿀 수 있다.
2. SET 교사들이 옮길 시간에 비어 있다 (다른 학년 SET·공통 수업·배정 불가 포함).
3. 순환 교사 지정도 회차와 함께 옮긴다 (또는 새로 정한다).
4. 시수, 선 수업, 부분 SET 반 겹침, 전체/부분 SET 동시 금지를 지킨다.
5. 같은 SET 하루 1회를 원하면 함께 검사한다.

SET 위치를 쓰는 다른 기능(교과 블록 칠하기 검사, 배정 불가-SET 충돌 경고, 버전 저장)도
결과 칸을 그대로 읽으므로 영향이 없다.

### 7.3 이전 실험과의 관계

- v3 프로토타입(교환 개선): 학년 **세로줄 맞바꾸기**로 SET 회차를 옮겼다.
  그 학년 모든 반의 두 시간 칸이 통째로 바뀌므로 SET 회차의 모든 반이 함께 움직였고,
  교사 묶음(순환 지정 포함)도 따라갔다. 같은 SET 하루 2회, 배정 불가, 다른 학년과의 교사 충돌은 감점으로 막았다.
  같은 줄의 공통 수업도 함께 움직였지만, 공통 수업은 원래 옮길 수 있으므로 문제 없다.
- 정수계획법(SET 자유): SET 회차 위치 변수가 그 SET의 모든 반을 함께 차지하고,
  순환 교사는 회차별로 다시 정했다. 같은 SET 하루 1회는 필수로 두었다.
- 두 실험 모두 **회차 단위**로 옮겼다 (한 SET의 여러 회차가 각각 다른 시간으로 갈 수 있음).
  반 일부만 떼어 옮기는 경우는 없었다.

### 7.4 통화로 확인할 예외

외부·순회 교사, 특별실, 학교 간 공동 교육과정, 학교가 정한 배치 패턴(대각선 순환 등),
같은 SET 하루 2회 허용 여부, 연속 2시간(블록) SET.

## 8. 확정 정책 (2026-10-16)

1~3단계 실험 결과를 바탕으로 확정한 정책이다. 이 절이 위의 "옵션·미결정" 항목보다 우선한다.

### 8.1 SET 배치

| 항목 | 정책 |
|---|---|
| 사용자 배치 | 사용자가 미리 배치한 SET 회차만 고정한다. 나머지 회차는 자동 배치한다. ([정책 실험](v3-set-policy-test.md): 미고정 배치는 효과 없음) |
| 같은 SET 같은 날 | 자동 배치는 같은 SET을 하루 한 번만 둔다. 사용자가 그 SET을 고정해 둔 요일에는 같은 SET을 자동 배치하지 않는다 |
| 예외 | 모든 요일에 한 번씩 놓아도 남는 회차가 있을 때만 같은 요일에 추가한다. 추가는 **층층이 채운다**: 모든 요일이 2회가 되기 전에는 어느 요일도 3회가 될 수 없다 |
| 순환 교사 | 사용자가 지정한 담당은 유지하고, 지정하지 않은 회차는 생성 단계에서 정한다 (고정 SET 포함) |

같은 SET 요일 배분 규칙(명세 H12)을 수식으로 쓰면 다음과 같다. 사용자가 고정한 요일별 회차 수를 F_d, SET 회차 수를 u, 요일 수를 D라고 하자.
- 층 높이 L: Σ_d max(F_d, L) ≥ u 를 만족하는 가장 작은 정수
- 요일별 총 회차 c_d: max(F_d, L−1) ≤ c_d ≤ max(F_d, L)
- 고정이 있는 요일의 자동 회차: c_d − F_d ≤ max(0, L − F_d)

예시:
- 주 3회, 고정 없음 → L=1. 서로 다른 세 요일에 한 번씩.
- 주 3회, 화요일에 2회 고정 → L=1. 화요일에는 더 놓지 않고, 남은 1회는 다른 요일에.
- 주 7회, 고정 없음 → L=2. 다섯 요일 모두 1회 이상, 그중 두 요일만 2회 (2·2·1·1·1).
- 주 11회 → L=3. 모든 요일 2회 이상, 한 요일만 3회.

### 8.2 목표 달성 기준과 결과 제공

- 근접 기준: 이론상 최선(하한) 대비 **10% 이내와 6점 이내 중 너그러운 쪽**
- 목표 달성 여부와 관계없이 결과를 제공한다. 결과마다 다음을 함께 보여준다.
  - 점수와 항목별 수치(점심 연강, 3연강, 동일 교과)
  - 이론상 최선 (확정되지 않았으면 범위)
  - 근접 기준과 달성 여부
- 미배치가 있는 결과는 시간표로 제공하지 않는다(생성 실패). 최소 미배치 수와 원인을 안내한다.

### 8.3 알고리즘과 실행

- 3단계에서 비교한 세 가지 로직을 모두 구현한다. 각각 별도 버튼으로 실행한다.
  - A. 탐색
  - B. 정수계획법
  - D. 혼합
  - SET 먼저 고정 방식은 기존 v2 버튼이 그 역할을 한다.
- 동시 실행과 작업 대기열(큐)은 배포 방법이 확정된 뒤 결정한다. 지금은 로직 구현과 비교까지만 확정한다.

### 8.4 탐색 시간

| 항목 | 정책 |
|---|---|
| 기본 | 5분 |
| 진행 표시 | 현재 최선 점수, 이론상 최선(또는 범위), 경과 시간 |
| 중지 | 사용자가 중지하면 그 시점의 최선 결과를 보여준다 |
| 최대 | 30분. 끝난 뒤 사용자가 이어서 더 돌릴 수 있다 (현재 최선에서 이어 감) |
| 조기 종료 | 성공 기준보다 엄격한 기준에 들고, 그 뒤에도 일정 시간·횟수 더 탐색해 개선이 없을 때 끝낸다 (세부값은 8.5) |
| 결과 수 | 점수가 좋은 순서로 최대 3개를 함께 보여준다 |

### 8.5 조기 종료·추가 탐색·결과 저장 (2026-10-16 확정)

목표는 **서로 다른 좋은 결과 3개**다. 기준에 처음 도달해도 바로 끝내지 않고, 3개를 모으려고 더 탐색한다.

| 항목 | 정책 |
|---|---|
| 최선 도달 | 점수 = 증명된 이론상 최선인 결과를 찾으면, 같은 점수의 서로 다른 결과를 3개까지 더 찾는다. 3개를 모으거나 추가 탐색 기준을 채우면 종료 |
| 엄격 기준 도달 | 이론상 최선 대비 5% 이내와 3점 이내 중 너그러운 쪽. 도달 후 같은 방식으로 추가 탐색해 결과 3개를 모은다 |
| 추가 탐색 기준 | 마지막으로 결과 목록(상위 3개)이 바뀐 뒤 **30초** 동안 바뀌지 않고, 혼합·정수계획법은 부분 재계산을 **20회 이상** 했을 때 종료 |
| 이어서 더 돌리기 | 5분 단위. 현재 상위 3개에서 이어 간다 |
| 서로 다른 결과 | 공통 수업과 SET 회차의 칸 배치를 비교해 **30칸 이상, 그리고 전체 수업 칸의 5% 이상** 달라야 다른 결과로 저장한다 (두 조건 모두) |
