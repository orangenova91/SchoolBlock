# v3 SET 정책 확인 자료 (담당자 통화용)

v3에서 SET 위치를 생성 단계에서 함께 정하려면, 현재 "SET을 먼저 배치(고정)"하는 방식이
**학교 운영상 필수인지, 편의를 위한 것인지**부터 확인해야 한다. 이 문서는 코드·기록에서
확인한 사실, 실험 결과, 통화에서 확인할 항목을 정리한다.

## 1. 코드·기록에서 확인한 사실

### 1.1 SET 개념 (코드 정의)

- SET = **이동수업(선택과목) 묶음**. 같은 SET의 과목들은 같은 시간에 열리고, 학생이 각자 과목 교실로 이동한다 (`lib/demo-seed.ts` 주석: "SET(이동수업/선택)").
- **전학년 SET**: 학년 전체 반이 동시에 참여(분반 수 합 = 학년 반 수). **부분 SET**: 일부 원학반만. **+α**: 원학반을 잠그지 않는 이동 분반.
- 같은 SET 안 과목은 시수가 같아야 한다(다르면 "단위 불일치").
- 한 과목을 여러 교사가 나눠 맡으면(순환), **SET을 모두 배치한 뒤 교시별 담당 교사를 추천**받아 정한다 (SET 화면 문구).

### 1.2 SET을 먼저 배치하는 이유로 볼 수 있는 것

| 근거 | 위치 | 성격 |
|---|---|---|
| 시간표 생성은 SET이 전부 배치돼야 실행됨 | `timetable/route.ts` (`wholeSetsPlacementComplete`) | 프로그램 구조상 요구 |
| 선 수업 칠하기가 SET 칸·SET 교사 충돌을 검사 | `subject-blocks.ts` `tryPaintSubjectBlock` | 입력 검증용 |
| 배정 불가가 SET 시간과의 충돌을 검사 | `teacher-constraints.ts` `findForbiddenSetConflicts` | 입력 검증용 |
| 순환 교사 배정이 SET 위치가 정해진 뒤에야 가능 | SET 화면 문구, `set-blocks.ts` | 입력 흐름상 의존 |
| 자동 배치는 **이미 놓은 SET은 유지하고 나머지만 채움** | `set-blocks-auto.ts` 주석 "Existing cells are kept" | **일부 수동 고정 + 나머지 자동이 이미 가능** |
| 커밋 기록: "시간표 생성 분기점_조건 추가를 먼저할지, 후에 할지 결정중인데 조건은 후에 작업하는 것으로" (2026-08-15) | git log | 단계 순서는 개발 중 설계 결정 |
| 커밋 기록: "초기 버전 완성_시간표 작성에 최적 모델은 아니라 평가함" (2026-08-16) | git log | 개발자도 최적 모델이 아님을 인지 |

**코드·주석·문서 어디에도 "학교 운영상 SET 시간은 반드시 미리 고정해야 한다"는 요구사항은 적혀 있지 않다.**
현재 구조는 ① SET이 가장 큰 제약이라 먼저 놓고 ② 이후 단계의 입력 검증과 순환 교사 결정을
쉽게 하기 위한 **설계상 순서**로 보인다. 다만 아래 1.4의 실제 학교 기반 데이터에는 의도된
규칙으로 보이는 배치가 있어, 운영상 이유가 있는지는 담당자 확인이 필요하다.

### 1.3 자동 배치에 들어 있는 SET 배치 선호 (`set-blocks-auto.ts` slotScore, 낮을수록 우선)

| 규칙 | 점수 | 의미 |
|---|---|---|
| 같은 SET이 같은 날 | +50 | 하루 1회를 강하게 선호 |
| 같은 SET이 바로 앞뒤 교시 | +20 | 연속 배치 회피 |
| 점심 직전·직후 교시 | +15 | 점심 앞뒤 회피 (→ 공통 수업이 점심 앞뒤에 몰리는 원인) |
| 같은 학년 SET이 같은 날 | +10/개 | 요일 분산 |
| 1교시 | +8 | 1교시 회피 |
| 같은 시간에 다른 학년 SET | −5 | 학년 간 시간 정렬 선호 |

이 선호들이 학교 요구에서 나온 것인지, 개발자의 판단인지 확인이 필요하다.

- 같은 SET이 같은 날 두 번(F: 화1·화7) 있으므로 "하루 1회"가 절대 규칙은 아닐 수 있다.

## 2. 일부 SET만 옮기는 방식의 효과 (실험)

v2 교환 개선에 "학년 열 교환"(한 학년의 두 시간을 통째로 바꿔 SET을 옮김)을 넣은 프로토타입으로,
고정할 SET 범위를 바꿔 측정했다. 같은 SET 같은 날 금지는 필수로 두었고, 데이터별 3회 평균(각 20초)이다.

| 고정 범위 | A: 점심 / 3연강 | B: 점심 / 3연강 |
|---|---|---|
| 전부 고정 (현재 v2) | 25.0 / 7.0 | 13.0 / 20.0 |
| 3학년만 이동 (2학년 고정) | 16.0 / 2.7 | 11.0 / 13.0 |
| 2학년만 이동 (3학년 고정) | 15.0 / 5.0 | 10.3 / 17.7 |
| 절반 이동 (각 학년 A·C·E) | 14.7 / 3.7 | 13.7 / 12.7 |
| 전부 이동 | **8.0 / 2.3** | **10.7 / 4.0** |

- 미배치는 모든 경우 0. 동일 교과 중복도 모두 0.
- A: 테스트 시간표(SET 11개). B: 실제 학교 기반 데모(부분 SET 포함, 원래 배치에 같은 SET 같은 날 1건).

해석

- **일부만 옮겨도 효과가 있다.** A에서 절반만 옮겨도 점심 연강 25 → 15, 3연강 7 → 4로 줄었다.
- **효과는 옮길 수 있는 범위에 비례**하고, 전부 이동이 가장 좋다 (특히 B의 3연강 20 → 4는 전부 이동에서만).
- 어느 학년을 풀지에 따라 효과가 다르다. A는 3학년(SET이 1~3교시에 몰림)을 풀 때 3연강이 크게 준다.
- 고정된 SET이 있는 시간은 학년 열 교환이 막히므로, 고정 SET이 많을수록 공통 수업의 이동 여지도 줄어든다.

→ **"반드시 고정할 SET은 먼저 고정 + 나머지는 생성 단계에서 자동"** 방식은 현실적인 대안이다.
  지금 SET 화면의 "일부 수동 + 자동 채우기" 흐름과도 맞다. 다만 고정 범위가 넓을수록 v3 효과는 v2에 가까워진다.

## 2-2. SET 전부 자동 배치 실험

SET을 사람이 놓지 않고 전부 자동으로 정하는 두 방식을 비교했다.

- **자동 고정**: 앱의 SET 자동 배치로 빈 상태에서 전부 배치한 뒤 고정 (v2 방식)
- **함께 최적화**: SET 위치를 생성 단계에서 공통 수업과 함께 최적화 (v3 방향)

같은 SET 같은 날 금지는 필수로 두었다. 정확 판정이 찾은 미배치 0 배치안에서 출발했고, 방식마다 3회씩 각 25초다.

| 데이터 | 수동 SET 고정 | 자동 SET 고정 | 자동에서 출발 → 함께 최적화 | 수동에서 출발 → 함께 최적화 |
|---|---|---|---|---|
| A 테스트 시간표 | 25 / 7 | 25 / 7 (수동 배치가 자동 배치 결과와 같음) | **10.3 / 0.3** | **8.7 / 0.3** |
| B 실제 학교 기반 | 12.3 / 20.7 | 25 / 9 | **8.3 / 4.0** | **9.0 / 3.7** |
| 측정 기준 시나리오 | – | 1 / 0 | **0 / 0** | – |
| 교사 부하 높음 | – | 11 / 1.3 | **6.3 / 0** | – |
| SET 비중 높음 | – | 19 / 0 | **0 / 0** | – |
| 부분 SET | – | 1 / 1 | **0 / 0** | – |

수치는 점심 연강 / 3연강 (3회 평균). 미배치·동일 교과 중복은 모두 0이다. 예외는 아래 "선택 중심 학교"다.

**SET 위치의 변화** (함께 최적화 후)

- 점심 앞뒤 교시에 놓인 SET 비율: 자동 배치 0~14% → **27~31%**.
  SET을 점심 앞뒤에 두면 공통 수업 교사의 점심 연강이 줄어든다.
- 같은 SET이 다른 요일의 같은 교시에 반복되는 수: 3~8 → 6~10으로 늘었다.
  대각선 순환 같은 규칙이 필요하면 조건으로 따로 넣어야 한다.
- 1교시 비율은 비슷했다 (9~17% → 12~20%).

**해석**

- SET을 전부 자동으로 정하면서 **함께 최적화하면 모든 데이터에서 크게 좋아졌다.**
  기준 시나리오·SET 비중 높음·부분 SET은 위반 0이 되었다.
- **출발점이 수동이든 자동이든 함께 최적화한 결과는 비슷하다** (A 8.7 대 10.3, B 9.0 대 8.3).
  사람이 처음 SET을 어떻게 놓았는지보다, 생성 단계에서 다시 정할 수 있느냐가 중요하다.
- 반대로 **현재 앱의 SET 자동 배치를 그대로 고정**하면 수동 배치보다 나을 게 없다
  (B: 점심 12.3 → 25). 자동 배치가 점심 앞뒤를 피하도록 되어 있어서다.
- **발견한 문제 – 단계 순서**: 선택 중심 학교 시나리오(배정 불가 10%)에서 앱 자동 배치가
  SET을 교사의 **배정 불가 시간에 18번** 놓았다. SET 단계가 배정 불가 단계보다 앞이라 자동 배치가
  배정 불가를 모르기 때문이다. 이 SET 배치를 고정하면 그대로 남는다(실험에서 위반 18로 집계).
  함께 최적화하면 0~2로 줄었다.
  → v3에서 SET을 생성 단계로 옮기면 이 문제도 함께 해결된다.

## 3. 통화에서 확인할 필수 사항

### A. SET을 미리 고정해야 하는 운영상 이유가 있는가

1. SET 시간을 **학교가 미리 정해야 하는 경우**가 있는가? 있다면 어떤 SET인가?
   - 순회·겸임·시간강사 교사의 출근 요일·시간
   - 학교 간 공동교육과정·온라인 공동교육과정 등 외부와 맞춘 시간
   - 특별실(과학실·음악실·컴퓨터실) 사용 시간
   - 학년 간 같은 교사 공유로 시간을 맞춰야 하는 경우
   - 교육청·학교 규정, 학생 이동 동선
2. SET 시간표를 **학생 수강신청이나 공지 전에 먼저 확정**해야 하는가? (일정상 SET만 먼저 정하는 관행)
3. 지난 학기 SET 시간을 **그대로 유지**하는 관행이 있는가?
4. 고정이 필요하다면 범위는? (전부 / 일부 SET / 특정 회차만 / "이 요일·교시대 희망" 수준)

### B. 실제 학교 데이터의 배치 규칙 의도

5. 3학년·기하의 **대각선 순환 배치**(요일마다 교시 이동)는 지켜야 할 규칙인가, 편의상 배치인가?
6. 2학년 전학년 SET A·B를 **오후 5·6교시에 교차**로 둔 이유는?
7. 제2외국어 부분 SET을 **1교시(및 7교시)** 에 둔 이유는? (교사 사정?)
8. 같은 SET을 **같은 날 두 번**(F: 화1·화7) 둔 것은 허용하는 것인가, 부득이한 것인가?

### C. SET 배치 규칙으로 둘 것

9. 같은 SET 하루 1회: 필수 / 선호 / 허용
10. 2시간 연속(블록) 수업이 필요한 SET 과목이 있는가?
11. 1교시·마지막 교시 회피, 점심 앞뒤 회피가 실제 요구인가? (현재 자동 배치의 선호)
12. 학년 간 SET 시간 정렬이 필요한가?

### D. 순환 교사·분반

13. 한 과목을 여러 교사가 나누는 경우 **누가 어느 회차를 맡을지**를 사람이 정해야 하는가, 자동으로 정해도 되는가?
14. 부분 SET의 **+α(이동 분반)** 의 실제 운영 방식과 제약

### E. 우선순위

15. SET 위치를 조금 바꾸면 점심 연강·3연강이 크게 줄어드는 경우(실험: 25 → 8), SET 위치 유지와 교사 편의 중 무엇을 우선하는가?
16. 생성 결과에서 SET 위치를 사람이 다시 조정하고, 공통 수업만 재생성하는 흐름이 필요한가?

## 4. 확인 결과에 따른 설계 갈래

| 확인 결과 | v3 설계 |
|---|---|
| 고정 필요 없음 | SET 전부 생성 단계에서 배치 (효과 최대: 실험 A 점심 25 → 8) |
| 일부 SET만 고정 필요 | SET 화면에서 고정 SET만 배치 → 나머지는 생성 단계에서 자동. 고정 SET은 v2처럼 움직이지 않음 |
| 시간대 희망 수준 | "희망 시간대"를 선호 조건(점수)으로 두고 생성에서 반영 |
| 배치 패턴(대각선 순환 등)이 규칙 | 패턴을 필수·선호 조건으로 모델에 추가 (같은 SET이 같은 교시에 반복되지 않게 등) |
| 전부 고정 필요 | v3의 SET 이동은 쓰지 않음. 개선은 공통 수업(v2)과 입력 단계 경고에 집중 |
