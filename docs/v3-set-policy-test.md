# v3 SET 배치 정책 실험 (2026-10-15)

## 1. 질문

v2에서는 우선 배치 단계가 결과에 영향을 주지 않아 자동화했다. SET에도 같은 질문을 던졌다.
사용자가 SET을 **배치했지만 고정하지 않으면**, 배치하지 않은 것(자동)과 무엇이 다른가?

판단 기준(사용자 지정):
1. 결과 품질에 영향을 주는가
2. 사용자가 둔 위치가 결과에 남는가 (선호를 반영한 것으로 해석할 수 있는가)
3. 최적해 탐색 시간에 도움이 되는가

하나라도 해당하면 "고정 / 미고정 배치"를 함께 검토한다. 모두 해당하지 않으면 **"배치한 SET = 고정, 배치하지 않은 SET = 자동"** 정책을 쓴다.

## 2. 방법

- 데이터: 체험용 시간표(교사 39명, SET 11개·35회차, 순환 과목 포함). 동일 교과 금지 전부 적용.
- 조건 2가지
  - C1 제약 없음
  - C3 배정 불가 5% + 선 수업 5%
- 사용자 배치 2가지
  - 실제 학교 배치(좋은 배치)
  - 요일 몰림 배치(나쁜 배치, C1만)
- 배치 범위: 전부 / 절반
- 처리 방식
  - **자동**: 배치하지 않음. 규칙을 지키는 시작 배치를 두고 함께 탐색한다.
  - **미고정**: 사용자 배치를 시작점으로 두되, 옮길 수 있다.
  - **선호**: 미고정과 같지만, 사용자 위치에서 옮기면 회차당 3점 감점한다.
  - **고정**: 사용자 배치를 그대로 둔다.
- 탐색 30초 / 120초, 각 3회 반복. 정수계획법으로 정책별 이론상 최선을 계산했다.
- 점수 = 점심 연강×3 + 3연강×2 + 동일 교과×3 (낮을수록 좋음)
- 유지율: 사용자가 둔 회차가 같은 시간에 남은 비율.
  자동 결과가 실제 학교 배치와 우연히 겹친 비율을 **우연 수준**으로 비교했다.
- 모든 탐색 결과는 미배치 0이었다.

> 고친 프로토타입으로 다시 측정했고, 모든 결과는 검증기를 통과했다. 판단(4절)은 바뀌지 않았다.

## 4. 판단

| 기준 | 결과 | 판정 |
|---|---|---|
| 1. 결과 품질 | 미고정 배치는 자동과 같거나 나빴다 (C1 26.3~30.3 대 31.3, C3 47.7~57.3 대 45.7). 나쁜 배치(요일 몰림)를 줘도 결과는 같았다 | 영향 없음 |
| 2. 위치 유지 | 미고정 유지율 4~30%는 우연 수준(13~23%)과 같거나 조금 높은 정도다. 탐색이 사용자 위치를 대부분 지운다 | 남지 않음 |
| 3. 탐색 시간 | 30초 결과도 같은 경향이었다 (C1 자동 28.0, 실제 학교 미고정 34.3, 요일 몰림 미고정 28.3). 시작 배치 시간은 모두 2초 이하 | 도움 안 됨 |

**결론: 미고정 배치는 v2의 우선 배치 단계와 같은 상황이다. 결과에 흔적이 남지 않고, 품질과 시간에도 도움이 되지 않는다.**
따라서 정책은 **"사용자가 배치한 SET = 고정, 배치하지 않은 SET = 자동 배치"**로 한다.

참고(확장 후보, 지금은 채택하지 않음): 위치를 **선호**로 반영하면 사용자 위치가 남는다(유지율 41~67%, 정확 최적화 시 최대 34/35).
대가는 점수 손실이다(최선 대비 +10~16점, 고정보다는 적음). 학교가 "가능하면 이 시간"을 원하는 경우에 쓸 수 있는 중간 단계다.
필요해지면 "희망 시간" 기능으로 따로 검토한다.

## 5. 함께 확인한 사항

### 5.1 고정은 비용이 크다 → 사용자에게 알려야 한다

- 실제 학교 배치를 전부 고정: 이론상 최선 72 / 81 (자유 24)
- 절반 고정: 27 / 52
- 요일 몰림 배치를 고정하면 125

정책상 고정 여부는 사용자가 정한다.
대신 **"고정 때문에 생기는 손실"**(고정 조건 최선 − 자유 조건 최선)을 계산해 보여주면, 사용자가 판단할 근거가 된다.

### 5.2 순환 교사 결정의 영향이 크다

SET 위치를 원래대로 고정하고, 순환 교사만 바꿔 계산했다(정수계획법 최적).

| 순환 교사 | C1 | C3 |
|---|---|---|
| 원래 데이터 (2학년 D SET 순환 과목 미지정 → 세 교사 모두 매 회차 바쁨) | 72 | 81 |
| 앱 추천(`recommendSubjectRotations`)으로 모두 지정 | 57 | 63 |
| 생성 단계에서 함께 최적화 | 53 | 57 |

- 순환 교사가 미지정이면 지금 앱은 나눠 맡는 교사를 모두 바쁘게 처리한다. 이 보수적 처리가 큰 손실을 만든다(15~18점).
- 생성 단계에서 함께 정하면 추가로 4~6점 좋아진다.
- v3에서는 사용자가 지정하지 않은 순환 교사를 **생성 단계에서 결정**한다(고정 SET 포함). 지정한 것은 유지한다.

## 6. 한계

- 학교 1곳의 데이터다. 배정 불가·선 수업은 원래 SET 위치를 피해 무작위로 만들었다.
- 탐색은 프로토타입이다. SET은 학년 세로줄 맞바꾸기로만 옮기고, 순환 교사는 시작 배치 때 정한 것을 유지한다.
- 유지율은 같은 SET의 같은 (요일, 교시) 기준이다.
