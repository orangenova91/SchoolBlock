# v3 계산 시간 안내 (2026-10-19 측정)

생성 화면에서 계산 방법별 **예상 시간**과 **추천 방법**을 보여 주기 위한 측정과 기준이다. 코드는 `lib/v3/estimate.ts`.

## 1. 측정 방법

- 사례 13가지: 테스트 시간표 6과 같은 체험용 학교(20반) 5가지, 가상 학교(학년당 4·8·12·16반) 8가지. 반 수, 교사 수(1인 시수), 배정 불가·선 수업 비율, SET 고정 여부를 바꿨다. (48반·SET 많음 1가지는 배치 불가 조건이라 뺐다)
- 사례마다 이론상 최선을 2분 계산(서비스의 자동 계산과 같음)한 뒤, 탐색·정수계획·혼합을 각각 5분 돌렸다. 16개를 동시에 돌려 서버가 바쁠 때와 비슷한 조건이다.
- **목표 도달** = 점수가 근접 기준(이론상 최선의 1.1배 또는 +6점 중 넉넉한 쪽) 이하가 된 시각. "—"는 5분 안에 못 닿음.
- 도구: `scripts/v3-perf/timing.ts` (사례 하나 × 방법 하나 → JSON 한 줄)

### 결론

- **작은 학교는 정수계획이 맞다.** 다만 혼합도 똑같이 늘 최선까지 가고 10초 정도 느릴 뿐이다.
- **중간 학교는 혼합이 기본으로 맞다.** 2분 안에 앞서는 경우가 대부분이고, 정수계획이 크게 실패하는 학교(체험용 20반 계열: 부분 SET·순환 교사·조건이 섞인 학교. 10분에 혼합보다 5~70점 나쁨)가 있다.
- **그러나 혼합이 늘 가장 정확하지는 않다.** 중간 학교 18곳 중 3곳은 정수계획이 5~10분에 혼합보다 좋은 최선을 찾았다 (SET 절반 고정 42 대 45.5, 교사 적음 15 대 20.5, 다른 학교 0 대 1.5). 혼합은 좋은 답 근처에서 멈출 때가 있다. → 화면 안내: "혼합 결과가 최선이 아니면 정수계획을 5~10분 더"
- **큰 학교는 혼합을 길게.** 사례가 2곳뿐이라 시간 범위는 넓게 잡는다. 탐색도 오래 두면 따라잡는 경우가 있었다(48반 2회차 10점 대 혼합 18점).
- 같은 학교·같은 방법이라도 무작위 값에 따라 결과가 꽤 다르다 (예: 30반 혼합 6점 / 0점). 결과 3개 비교와 이어 계산이 중요한 이유다.

## 3-3. 3차 측정: 큰 학교 20가지 × 4가지 방법 × 2회 × 15분 (2026-10-19)

- 크기 8단계(33·36·39·42·45·48·54·60반), 48반 조건 변화 8가지(SET 없음·적음, 교사 많음·적음, 조건 없음, 배정 불가 10%, 다른 학교 2곳), 36반 조건 변화 4가지. 모두 빠른 검사 통과

## 3-6. 혼합의 준비 시간을 줄였더니 왜 빨라졌나

### 혼합은 두 단계로 돈다

1. **시작 해 만들기 (준비)**: 탐색(담금질 탐색)으로 완성본을 하나 만든다.
2. **부분 재계산 (본 계산)**: 시간표의 한 구역(하루, 한 학년의 이틀, 오래 못 좋아지면 더 큰 구역)만 비우고, 나머지는 그대로 둔 채 정수계획으로 그 구역을 **가장 좋게** 다시 채운다. 이것을 반복한다. 한 번에 최대 15초.

### 준비 단계(탐색)는 이렇게 동작했다

- 시간은 **미리 정해 둔다**: 구간(5분)의 25% = **75초** (10초 이상).
- 무작위로 바꿔 본다: 한 반 안의 두 칸 맞바꾸기, SET 회차(학년 세로줄) 옮기기, 순환 담당 교사 맞바꾸기.
- 좋아지면 받아들이고, 나빠져도 **온도**에 따라 가끔 받아들인다 (막다른 길을 벗어나려고). 받아들일 확률 = exp(−나빠진 점수 ÷ 온도).
- 온도는 정해 둔 시간 동안 4에서 0.05로 **천천히 식는다**. 처음에는 나쁜 수도 많이 받아들이며 넓게 돌아다니고, 끝 무렵에야 좋은 답 근처로 모인다.
- 무작위 시작값(seed)이 있어 같은 입력이라도 회차마다 결과가 조금씩 다르다.

### 줄였더니 빨라진 이유

1. **식는 속도가 시간에 묶여 있다.** 준비 시간이 75초면 온도가 75초에 걸쳐 식는다. 좋은 답은 대부분 식는 끝 무렵에 나온다. 그래서 75초를 거의 다 기다려야 쓸 만한 시작 해가 나왔다. 20초로 줄이면 같은 과정이 20초 안에 압축된다. 시작 해는 조금 거칠지만 이미 완성본(미배치 0)이다.
   - 같은 현상을 탐색 단독에서도 봤다: 5분에 걸쳐 식히면 목표 도달 2.2분, 1분마다 다시 식히면 32초.
2. **본 계산이 훨씬 강하다.** 부분 재계산은 한 구역을 정수계획으로 "가장 좋게" 채워서 한 번에 여러 점을 줄인다. 무작위로 하나씩 바꿔 보는 탐색과는 힘이 다르다. 탐색이 75초 동안 줄일 점수를, 본 계산은 거친 시작 해에서 몇십 초면 줄인다.
3. 그래서 **"시작 해를 공들여 다듬는 시간"을 "본 계산을 일찍 시작하는 시간"으로 바꾼 것**이 이득이다.
   - 측정: 목표 도달 중앙 52초 → 18초.
   - 5분 뒤 점수도 같거나 좋다. 본 계산을 더 오래 했기 때문이다.

비유: 방 정리를 할 때 처음 75초 동안 물건을 이리저리 옮기며 대충 정리하던 것을, 20초만 대충 정리하고 바로 "서랍 하나씩 꺼내 완벽 정리"로 넘어가게 했다. 대충 정리가 덜 됐어도 서랍 정리가 훨씬 강해서 전체가 빨리 끝난다.

### 큰 학교는 왜 그대로 두었나

- 큰 학교는 20초 안에 거친 시작 해만 나오거나, 필수 위반·미배치가 섞인 시작 해가 나올 수 있다.
- 본 계산은 한 구역만 비우고 고치므로, 시작 해가 많이 거칠면 고칠 곳이 너무 많아 오래 걸린다.
- 측정에서 48반 1회가 243점(정상 회차 0~9점), 60반 1회가 132점으로 크게 나빠졌다. 그래서 31반 이상은 기존(75초)을 유지했다.
- 큰 학교의 적정 준비 시간(예: 반 수에 비례)은 더 측정해 정한다.

| 큰 학교 (31반 이상) | **혼합** | 대부분 첫 결과에서 거의 좋아지지 않음 (비추천) | 약 1~5분 (보통 2분 안팎, 5곳 중 1곳은 15분에도 못 닿음) | 대부분 15분에도 목표에 못 닿음 |

규모별 덧붙임 안내
- 작은 학교: 혼합과 정수계획 모두 최선까지. 혼합이 조금 더 빠르고, 정수계획은 최선임을 증명
- 중간 학교: 혼합이 가장 빠르고 안정적. 혼합 결과가 "최선"이 아니면 정수계획을 5~10분 더 (18곳 중 3곳에서 1.5~5.5점 더 좋았음)
- 큰 학교: 혼합이 가장 빠르고 정확함. 목표에 못 닿으면 미리 승인으로 5분씩 더
- 중간·큰 학교에서 SET이 6개 이하면: "SET이 적어 정수계획도 20초 안팎에 목표에 닿을 수 있음" (48반 SET 없음·적음, 12·24반 SET 없음·적음 측정)

"더 걸릴 수 있는 조건"으로 함께 보여 주는 것: 배정 불가가 교사 1명당 2칸 초과, 선 수업이 주당 수업의 5% 초과, 고정한 SET 칸.

## 5. 한계

- 1차 13가지·2차 32가지·3차 큰 학교 20가지 사례로 정한 대략적인 기준이다. 실제 학교는 SET 구성(부분 SET·순환 교사)이 더 다양할 수 있다. 같은 규모라도 SET 구성(부분 SET·순환 교사)과 조건에 따라 몇 배씩 차이 난다 (예: 20반 체험용 학교는 24반 가상 학교보다 어렵다).
- 목표 도달 시간은 이론상 최선이 얼마나 정확한지에 달려 있다. 큰 학교는 2분 계산으로 하한이 약하게 나와 목표가 실제보다 엄격해질 수 있다.
- 실제 학교 자료가 쌓이면 다시 측정해 기준을 고친다 (`scripts/v3-perf/sweep.ts`).

계산·진단 버튼은 **지금은 모두 둔다**. 화면을 조정한 뒤 아래 검토를 바탕으로 최종 결정한다.

**계산**
