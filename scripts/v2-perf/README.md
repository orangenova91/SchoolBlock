# v2 성능 측정

시간표 생성 로직 v2(`docs/v2-timetable-logic.md`)를 여러 학교 조건에서 측정하는
스크립트다. DB를 쓰지 않고, 학교 데이터를 메모리에서 만들어 실제 v2 경로
(사전 검사 → 배치 가능하면 생성)를 그대로 실행한다.

## 실행

```bash
npx tsx --tsconfig ./tsconfig.json scripts/v2-perf/run-all.ts 2026-10-15 6 3
```

인자: 결과 폴더 이름, 동시 실행 수, 시나리오당 생성 반복 수.
교환 개선은 시간 기준으로 끝나므로 동시 실행 수는 CPU 코어 수보다 넉넉히 낮게 둔다.

시나리오 하나만:

```bash
npx tsx --tsconfig ./tsconfig.json scripts/v2-perf/run.ts base 3
```

보고서만 다시 만들기:

```bash
npx tsx --tsconfig ./tsconfig.json scripts/v2-perf/summarize.ts scripts/v2-perf/results/2026-10-15
```

## 파일

| 파일 | 내용 |
|---|---|
| `school.ts` | 학교 데이터 생성기 (교육과정 틀, 교사 배정, SET 배치, 배정 불가, 선 수업, 동일 교과 금지) |
| `scenarios.ts` | 측정 시나리오 목록 (기준 + 축별 변형 + 현실·극단 조합) |
| `run.ts` | 시나리오 하나 측정 (JSON 줄 출력) |
| `run-all.ts` | 전체 병렬 측정 + 보고서 |
| `summarize.ts` | `report.md` 생성 |
| `results/<이름>/` | 시나리오별 원본(jsonl)과 `report.md` |

## 학교 데이터 생성 규칙

- 주당 32시간 (월·화 7교시, 수~금 6교시). `slack`만큼 교시를 늘리면 반마다 빈 칸이 생긴다.
- 교육과정 틀 (2022 개정, 고교학점제 일반고 편제 단순화)
  - 1학년 공통: 공통국어·수학·영어 4, 한국사·통합사회·통합과학 3, 과학탐구실험·체육·예술·정보 2, 창체 3
  - 2·3학년: 학교 지정 과목 + 선택 묶음(SET). SET 비중(2학년/3학년): 없음 0/0, 낮음 19/38%, 보통 38/63%, 높음 50/75%
  - 참고: 2026학년도 입학생 편제 예 – 통합사회·통합과학 각 8학점, 과학탐구실험 2학점, 국·수·영 학교 지정 17~24학점,
    2학년 지정 11학점·선택 18학점/학기, 3학년 개별 선택 27학점 (지역내일 2026.10.07, 안산 일반고 편제 비교)
- SET은 분반마다 과목 하나·교사 한 명. 같은 SET 안에서 교사는 한 분반만 맡는다.
- 교사: 교과(부서)별 시수 합 ÷ 평균 목표(`avgLoad`)로 교사 수를 정하고, 적게 맡은 교사부터 나눠 준다.
  1인 상한 22시간. 창체·교양은 시수가 적은 교사(담임)에게 준다. 교과마다 최소 1명을 두므로 실제 평균은 목표보다 낮을 수 있다.
- SET 배치: `auto`(앱의 자동 배치) / `spread`(요일 분산) / `lunch`(점심 앞뒤 우선) / `avoidLunch`(점심 앞뒤 회피) / `concentrated`(특정 요일 몰림).
  교사·반 겹침은 항상 피하고, 같은 SET을 같은 날 두 번 넣지 않는다.
- 배정 불가: `random`(교사별 빈 시간의 비율) / `dayOff`(교사 비율만큼 요일 하나 통째) / `halfDay`(교사 비율만큼 이틀은 오전만). 교사마다 시수+4칸 여유는 남긴다.
- 선 수업: 공통 수업의 일정 비율을 무작위의 들어갈 수 있는 칸에 고정.
- 난수 시드가 고정이라 같은 시나리오는 항상 같은 학교를 만든다.
